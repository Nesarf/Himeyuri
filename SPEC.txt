====================================================================
0.5 看板娘
====================================================================

本语言的看板娘是 小一孁こはね（中文名 小一孁琥珀音）——山丹与火正是她卍解所现之力，
所以语言的名字与她的力量是同一处来处。她在文档与命令行迎客，但不进机房：
错误信息、安全告警、测试输出与数据本体里一律不出现。形象卡与界限见 MASCOT.txt。

====================================================================
1. 用途宣言
====================================================================

HMYR 是一门通用语言：同一份语义，既能在脚本档位立刻跑起来，也能拧到硬档位进实时音频回调。
它的主张只有一句——每一个论断都可被检验。

定位：车间／平台类语言。Himeyuri 工作的逻辑类型本身就是一个开发平台——人们应当能在它之上
再开发出新的开发平台、新的工具链乃至新的语言。由此推得的六条推论（方言即库 · 宏是核心能力 ·
要能驱动工具 · 要能自省与生成 · 向外三向接口 · 包管理沿用声明-许可-哈希的纪律）写在
design/PLATFORM.txt 里，每条都挂落点与里程碑。

这句话不是口号，它决定了下面所有取舍：

  ・宁可没有某个特性，也不要一个「说不清什么时候会出错」的特性；
  ・错误信息是规格的一部分（有编号、可搜索、说得清找过哪里）；
  ・依赖、效果、精度、内存行为都要能被声明，并被工具核对。

[验] 用途宣言的验收方式：里程碑 M1–M7 全部达成（M5 嵌入、M6 工具链、M7 自举各有对应用例），且 KPB 的谱／混／音色用 HMYR 写成并能往返。

2. 核心语言
====================================================================

核心要窄。窄才守得住，宽的部分交给标准库与生态。

— 2.1 词法

[定] 源文件为 UTF-8（接受 BOM，写入时不写）。行结束 LF 或 CRLF 都接受，语义与换行无关。

[定] 标识符允许 Unicode 字母，但必须归一化到 NFC，且对同形异码（homoglyph）给出警告。
理由是我们自己吃过教训：文件识别那套「按内容不按名字」「全量 Unicode 但不得有破损」的经验值直接搬过来。

[定] 注释：// 行注释、/// 文档注释、/* ... */ 块注释，而块注释可以嵌套
（src/lexer.mjs 用深度计数实现，不是「遇到第一个 */ 就停」）。后者是明确的取舍 ——
省下「注释掉一段代码却因为里面已有块注释而失败」的经典坑。

[定] 语句结束：换行即分界。这一条 2026-10-20 从 [议] 升上来，因为实现一直就是这么跑的；
续行靠显式规则（行尾运算符或括号未闭合），而唯一放宽的位置是 if 与 else 之间（见 2.2）。

— 2.2 文法（骨架 EBNF）

module      = { import } { decl } ;
import      = "import" path [ "as" ident ] [ "rev" int ] ;
decl        = fn | type | const | var | effect | macro ;

fn          = [ "pub" ] "fn" ident [ typeParams ] "(" [ params ] ")" [ "->" type ]
              [ effects ] [ "realtime" ] [ contracts ] block ;
params      = param { "," param } ;
param       = [ "own" | "borrow" ] ident ":" type [ "=" expr ] ;
effects     = "effects" "(" [ effect { "," effect } ] ")" ;
contracts   = { "requires" expr | "ensures" expr } ;

type        = ident [ typeArgs ] [ "?" ] | tuple | fnType ;
expr        = literal | ident | call | field | index | record | binary | unary
            | if | match | block | lambda ;
record      = "{" [ field { "," field } ] "}" ;
field       = ident ":" expr ;

stmt        = "let" ident [ ":" type ] "=" expr
            | "var" ident [ ":" type ] [ "=" expr ]
            | assign | return | ifStmt | whileStmt | block | exprStmt ;

[实] 这一份文法比实现宽，而宽出来的地方要说清：
      module 里的 import 与 decl 在解析后是同一层的两个列表（imports 与 decls），
      而 decl 里的 macro 只有宿主那一层认 —— 子集那一层明说不含 match 与宏。
      所以逐条对照时，认得的窄是设计，不是缺口。
      文法里三处是这一轮补的：import 的 rev、fn 的 realtime、decl 的 var ——
      它们都实现了，而文法没跟上，那种过期比缺一条更误导。

[实] 换行是语句分界，但「if 块之后」这个位置不是：} else { 与 } 换行 else { 读成同一棵树。
     2026-10-20 放宽。实现在 src/subset-parse.mjs 的 if 那一支：先往前看，隔着若干换行之后
     真是 else 才把那些换行吃掉 —— 无条件跳过空行会吃掉下一句的换行。
     其余场合换行照旧作分界；这条边界是「这里放宽了」，不是「随便换行都行」。

[验] 文法进符合性套件：每个产生式至少一条正例与一条反例。

— 2.3 类型与求值

  ・静态类型 + 局部推导：let x = 1 推出整数类型；函数签名必须写明：[定]
  ・泛型：单态化（不做运行时反射式泛型）；约束用 interface：[定]
  ・空安全：非空是默认，可空必须写 T?；T? 到 T 的转换必须显式：[定]
  ・错误处理：Result[T, E] 是一等公民，? 传播；异常只用于「不该发生」（panic）：[定]
  ・可变性：let 不可变、var 显式可变：[定]
  ・可变性与赋值：只有 var 声明的名字可以赋值；给 let 赋值，或给不在作用域里的名字赋值，报 HMYR-R0150。
  ・具名数据：{字段: 值, ...} 构造具名记录。字段名是标识符或关键字——在这个位置上关键字不保留，
    因为描述一份声明的记录天然想用 type、pub、effects 这类词作字段名（自举正是撞在这里才补的这条）。
  ・契约的位置：requires 与 ensures 可以写在签名之后的各自行上，也可以紧接同一行；规范排版用前者。
  ・单元素元组：(x) 是分组，(x,) 才是只有一个元素的元组——数据语言要靠它把一串元组串起来。
  ・序列的拼接：两个元组用 + 拼成一个（数据语言要能递归地长出一串东西）；元组与其它值相加报 HMYR-R0130。
  ・可变数组：数组(元组) 把元组复制成可变数组；设(数组, 下标, 值) 原地改，交回同一个数组。下标读写与 len 对数组与元组一样；越界报 HMYR-R0152，设 拿到不是数组的值报 HMYR-R0151。元组仍然不可变 —— 从元组造出的数组改多少，原元组都不动；+ 对数组与元组都拼成一个新元组，从不就地改。
  ・2.5 实现的可移植性：本语言自身的源码只许使用可移植的内置（Node、Deno、Bun 都提供的那几样），不许依赖宿主的专有模块。
  ・编号的分布：E0001-E0099 词法 · E0100-E0199 语法 · W0001-W0099 警告 · R0100-R0199 运行期 · R0200-R0299 效果与能力 · R0300-R0399 预留（三区模型）。登记表在 conformance/codes.mjs，每个编号写明含义；程序能触发的编号必须有符合性用例，实现自身的故障标记为 internal，尚未实现的标记为 planned。
  ・2.6 内置函数的边界：求值器提供的每个内置函数都必须落在标准库第一圈内；多出来的要么入选，要么删掉。，用 .字段 读取；这是 KPB 那类数据语言要用的形状。is_letter、is_mark 、nfc、read_text、read_line／read_lines（按行读：偏移与下一处；语言里没有文件句柄）、write_text、write_bytes／f64_bytes／pack_value（自举打包：字节出口、双精度的位、值的编码）、run_program、console_codepage 、split、record_new／field_get／field_has／field_names、index_new／index_set／index_get／index_has／index_len／index_keys（按键查的东西：键是任意字符串，见 design/INDEX.txt）、thr_spawn／thr_join／thr_cancel／thr_count、repo_path／python_path／temp_path／file_exists 与 term_size／term_clear／term_escape／term_color／term_hide／term_show、sleep_ms、floor、slice／ord／chr／to_upper／to_lower／to_int、cwd／home_dir／chdir／argv／print_err、key_push／key_available／key_read、locale_env／locale_current／locale_set／key_start（字符分类）同属第一圈：它们是文本层最小的一对原语。
  ・下标：从 0 开始，可下标的值是元组与字符串；越界报 HMYR-R0151，不可下标的值报 HMYR-R0152。
  ・求值顺序：左到右；实参自左向右求值；规格写明，不留实现自由：[定]
  ・整数溢出：默认检查并报错；硬档可显式关闭（@wrapping）：[定]
  ・单位与量纲：核心不内置；标准库提供 CAD／音频所需的量纲类型：[议]
  ・数值精度：标准库给有理数与区间数；CAD 那类场景不许「浮点凑合」：[议]

[验] 求值顺序、溢出、空安全：各有一组符合性用例，且用例本身就是文档。

— 2.4 三只旋钮：软硬兼具的实现

这是本语言最核心的设计，也是「上下限都宽」的落点。

  ・效果声明：不写，随便调用：签名写明能碰什么：effects(file, net, process)
  ・所有权与借用：不检查，托管分配：own / borrow 检查；竞技场分配；无 GC 路径
  ・契约与不变式：不写：requires / ensures / invariant，能证则证、不能证则运行时查

三条硬条款：

1. [定] 同一份语义：三只旋钮只改检查强度，不改语义。关掉检查的程序与打开检查的程序，行为一致——不一致即为编译器缺陷。
2. [定] 编译器必须自报：它要说清「我证到了什么、没证什么、按哪一档检查的」。默认沉默不算通过。
3. [定] 不许偷偷联网：未声明 net 效果的程序无法发起网络调用；起进程同理（process），读文件同理（file）——凡碰得到外面世界的内置函数，都要在调用处通过效果检查。

[验] 关档与开档的程序跑同一组用例，结果必须逐项一致；编译器自报由工具链用例核对。

— 2.7 内存的三个区与模块级名字

两件事并排写在这一节，因为它们回答同一个问题：一个值活到什么时候。

三个区（细节、实测与那次否定的结论都在 design/MEMORY.txt）：

  arena    一次释放全部。alloc 分块，close 带走整区，freeze 把一块交给托管区、
           adopt 把它收回来。块按下标存内容（存／取），越界给 R0151。
  owned    一个持有格只装零个或一个值。取出即转移 —— 取走之后源那边空了，
           于是「两处都声称拥有它」在运行期不成立。放第二次、或关掉之后再放，
           给 R0305；取空的给 R0306。
  managed  运行时回收，且不移动 —— 插画与 CAD 要把缓冲区交给 C 与系统 API，
           移动式回收会把 FFI 变成一片补丁地。

三条硬规矩：

1. [定] 不静默换区：换区必须显式转换（freeze／adopt），违者是装载时的错。
2. [定] 不许逃逸：一块内存不许活过它的区。装载时拒（R0301），不是运行时的意外。
3. [定] 托管对象不移动。

[验] test/zone.test.mjs（记账与两条转换，十六项）· test/zone-static.test.mjs
（装载时的四条静态判据，含整仓零错误）· test/zone-self.test.mjs（四台机器同一个答案）
· test/owned.test.mjs（第三区，四台）。

模块级名字（细节在 design/GLOBALS.txt）：

  ・顶层 const 与顶层 var 都是模块级的。const 的名字不能重绑，var 的可以。
  ・[定] 初始化按源码顺序、依赖在前；跨模块时按 import 的顺序。
  ・[定] 可见性平铺：模块级名字住一条平铺的表里，重名先到者赢，
    加载器为此报 W0302，而不是让它静默发生。

[验] test/global-var.test.mjs：四台机器跑同一个程序得同一段输出，且写 const 被拒。

实时档位的四条约束挂在 2.4 的第三只旋钮上（fn f() realtime），它的静态四条与那支
最坏耗时的标尺在 design/MEMORY.txt 第 3 节。

[悬] 仍然没有的两件，写在这里而不是留给读的人去发现：作用域结束自动释放只到帧级
（语言没有块钩子），而实时档位的运行时那一半只在 C 那台成立（零停顿与最坏耗时上界 ——
前者今天断言不出，只能度量，见 design/MEMORY.txt 第 3 节）。

— 2.8 语言档案与编码

一套档案的身份是「语言乘上编码」，不是一个语言名字。中文既可能是 GBK 也可能是 UTF-8，
而两者的字节不同；只按语言切，就会在同一份档案里藏两种事实。

四套，而不是三套：zh-CN.gbk · zh-CN.utf8 · ja-JP.shift_jis · en-US.utf8。
中文给两种编码，因为这一层最容易被「语言」这个词骗过去。

一套档案里有：主要文字、源码编码、输入输出编码、标识符允许的字符范围（由文字推出）、
大小写折叠、排序与数字格式、错误信息的语言、写出时是否加 BOM。

五条规矩，比字段更要紧：

1. [定] 默认档案由环境决定，但必须能查、能覆盖。
2. [定] 跨档案交换数据一律按显式编码；档案只管本机的默认，不管这段字节是什么。
3. [定] 不许猜码：当前档案是 UTF-8 而读到非法字节时报错，不猜成别的编码。
4. [定] 编号稳定，文字随档案：HMYR-E0006 永远是这个编号，而它的说明用档案指定的语言。
5. [定] 档案绝不影响语法与求值。数字格式、日期写法、排序都不许改变一份程序的含义。

第五条是硬规则。档案只作用于输入输出边界与人类可读文本；一旦它开始影响语义，
同一份源码在不同档案下会有不同意思，那是最坏的一类 bug。

[验] test/locale.test.mjs：四套档案的身份、五条规矩里能判的四条（默认可覆盖、
显式编码、不猜码、编号稳定），以及一条「同一份程序在四套档案下算出同一个数」——
那一条是第五条的可执行形状。

[验] test/i18n.test.mjs 与 test/corpus.test.mjs：字符串、排序与分词在四套档案上的行为。
细节与四套档案的来处见 design/LOCALES.txt。

那两栏（排序与数字格式）2026-10-27 定了规矩，而定的是「它们不进档案」：

[定] 数字的写法不进档案。str(数) 在四套档案下给出同一串 —— 第五条硬规则落到输出
那一头的形状就是这一句。要「按档案格式化」的时候，那是一个独立的函数
（fmt_number(值, 档案)），而它不是 str。

[定] 排序默认按码点。语言今天没有 sort 内置；而它出现的那一天，默认必须按码点 ——
那一条不依赖任何表，四台都能复现。要按档案排就得在调用处显式写出来
（sort(列, 档案)），于是「按什么排」永远看得见。

[定] 列目录的顺序由能力层排定，不留给调用者 —— 目录顺序是文件系统的习惯，
而清单要能逐字节比对。这一条已经落地（read_dir 交回排好序的元组）。

[验] test/locale.test.mjs 那两条：「两种档案下算出同一个结果」与「两个档案下数字写成
同一串」（3.5 与 1234567 —— 最容易被本地化的两个数）。

— 2.9 并发

三件套：结构化并发 · 进程式隔离 · 消息传递。

1. [定] 结构化并发：任务只能从它被创建的那一层派生，而那一层退出时必须等它 ——
   没有「忘了 join 的孤儿任务」这种状态。
2. [定] 进程式隔离：两个任务之间没有共享可变状态，隔离是硬的（每一份有自己的求值器实例）。
3. [定] 消息传递：任务之间只传值，不传区。区的寿命不跨任务，实时档位的回调不许被暂停。

[验] test/threads-cvm.test.mjs（11 项）与 test/thr*.test.mjs：句柄的生命周期、
取消、计数，以及「两块内存真的不共享」。那几条是隔离的可执行形状。

[定] 效果在并发下的传播（2026-10-27 定，理由见 design/CONCURRENCY.txt 的 2.1.6）：
分两层。派生处这一层今天有判据 —— 派生者必须自己声明 thread 效果，
否则 thr_spawn 被 R0201 拒。任务那一层今天做不到，原因要写准：任务是一段
源码字符串（thr_spawn 收的是源码与入口名），它的 effects 在那段字符串里，
语言在派生的时候看不见它，所以没有「任务的效果集」可以与派生者相比。
等任务成为一等值（函数值）的那一天，收窄才有落点；而函数值要先有。
在那之前，语言能保证的只有一句：派生这件事本身被声明过。

[定] 取消的两种形态，分界在「谁能被语言调度」（2026-10-27 定，取舍见
design/CONCURRENCY.txt 的 2.1.5）：任务树内的取消是结构的（取消父即取消子树）；
语言自己调度的任务用协作式（在取消点上让出）；借宿主能力起来的任务用强制式
（thr_spawn 与 thr_cancel 那一层）。用协作式描述宿主那一层会说谎，用强制式描述
语言这一层会撕开隔离 —— 所以两条都写明，而不是选一条。

细节、六个反例与验收清单见 design/CONCURRENCY.txt。

— 2.10 与外面的世界：字符串与缓冲区的约定

这一节原来是一份 [悬] 的诚实写法：列出三条已经定下来的事实，与三个还没答的问题。
2026-10-27 三个问题定下来了，所以下面从「问题」变成了「条文」—— 而条文要紧的地方
不在于答案本身，在于每个答案的代价都写在 design/FFI.txt 里，谁要改先看那一页。

三条已经定下来的事实：

1. [定] 字符串在机器里是 UTF-16 码元序列，不是字节。所以「把这个字符串给 C」这件事
   从来不是一次指针传递，而是一次编码决定 —— 而编码由档案那一节（2.8）管。
2. [定] 字节是 u8 的元组或数组，两者可下标、可切片，与字符串不是同一个类型。
   read_bytes 与 write_bytes 走这一头，read_text 与 write_text 走那一头。
3. [定] 值带标签（空 / 数 / 串 / 布尔 / 元组 / 数组 / 记录 / 索引）。C 那台的判词与
   另外三台逐条对应，所以「一个值是什么」在四台上是同一个问题。

三个问题的答案（2026-10-27 定，取舍与代价见 design/FFI.txt）：

  ・[定] 谁分配：语言这一侧。外面拿到的是窗口，窗口不是新内存，是原来那一块的一段。
    需要外面填的时候给可写窗口（今天还没做）。
  ・[定] 谁释放：语言这一侧。窗口的有效期就是那次调用 —— 外面从来没有拥有过它，
    所以「谁释放」在边界上不成为问题。
  ・[定] 怎么过界：显式说明，且加一条更硬的规矩 —— 跨边界一律传字节，不传字符串。
    字符串要过界必须先显式编码成字节，而那一步就是答案。这条守住 2.8 的第三条：
    没有隐式编码，就没有可猜的地方。

最小的可执行形状：[定] bytes_view(字节们, 起, 长) 交出一段不拷贝的窗口。
它不引入新的所有权（「谁分配」的答案是原来那块）、不引入新的生命周期概念
（「谁释放」不需要新机制）、也不引入隐式编码（窗口是字节）。

[验] test/ffi.test.mjs：四台一致、越界给 R0151、窗口读出来与原处相同、
以及「改动原处之后窗口看到新值」—— 最后那一条是「不拷贝」的可执行证据。
今天能验的仍然包含前面三条事实：test/c-vm.test.mjs 逐条比对四台的判词，
test/f64.test.mjs 验字节与浮点的往返，test/locale.test.mjs 验编码那一条。

仍然不做的：真的调一个 C 函数（那要 extern 声明、链接约定与「符号名怎么找」）、
可写窗口（要回答「外面改坏了谁负责」）、字符串直接过界（按上面第三条，它不该存在）。

细节见 design/FFI.txt（三个问题的取舍）与 design/FILETYPE.txt（容器型）。

— 2.11 文件类型

判据只有一条：读它的程序要不要先知道它是什么。要，就给扩展名；不要，就给目录名。

九个扩展名，按「文件怎么被读」分：

  hmoca 源码 · hmoks 字节码 · hmtn 种子 · hmnkk 一般文本 · hmoug 配置文本
  hmknst 错误码与用例 · hmkit 套件清单 · hmkgr 乐曲与场景 · hmbnso 说明书

[定] 源码只有一个扩展名，而不是「常规」「特殊」两个。理由是运行档位不是文件类型，
是这一个文件对运行时的要求 —— 它该写在文件头、随内容走，因为同一份源码可能两种
情形都跑。扩展名只有一位，让它说「这是什么」，不说「它想怎么跑」。

三个名字是目录或集合，不是扩展名：hmkoudi（对照实现）· hmszrbk（工具链）· hmzsnt（语料）。
它们改了不会让任何工具换读法 —— 它们让读代码的人知道这一格是什么。对照实现不参与
跑程序，它的存在只为「两台机器同一个答案」这一句。

另有一个容器型（hm-ittgn-krgn-m），判据与上面九个都不同：上面按「文件怎么被读」分，
它按「整包怎么被装、被跑、被转换」分。它的两种条目、十二层规则与往返转换见
design/FILETYPE.txt 第三节。

[验] test/package.test.mjs 与 test/distro.test.mjs：九个扩展名各自由谁读、三个名字
出现在目录里、以及容器型的往返。docs 那一条验的是「说明书本身也是 hmbnso」。

3. 借来清单（学自谁、为什么）
====================================================================

集百家之长，收的是最扎实的想法，不是最多的特性。每条都写明来处与理由。

  ・Go：语法小、编译快、gofmt 式「格式化即法律」、换行即语句结束：降低入门与协作成本，工具争议一次解决
  ・Rust：无空指针、穷尽匹配、所有权/借用作为可选硬档：安全与性能不必二选一，但不当成唯一档
  ・Dart：空安全从第一天设计进去；VM/AOT 双路：后补空安全的代价我们有目共睹
  ・C# / Java：丰富类型系统、泛型、大标准库、LSP 与调试器：「能用」的门槛在这一块
  ・Elixir / Erlang：进程隔离与监督树；「让它崩，然后有人管」：多用途软件里，容错是常态需求
  ・Python：可读语法、REPL、开箱手感：软化下限，让脚本档位真的顺手
  ・JavaScript：async/await 的顺手；「哪儿都能跑」的部署观：上限：并发表达与分发
  ・Ada / 形式方法：契约、不变式、可证明的子集：可检验这条主张的技术来源
  ・Swift / Kotlin：渐进披露、密封类型、可空性：让宽范围共存而不互相污染
  ・Lisp / Smalltalk：活环境与热重载（作为工具，不是核心）：音色与混音编辑需要「不重启就改」

[验] 每条「借来」必须在标准库或工具链里有对应物。只在文档里出现的借用，算装饰。

====================================================================
4. 不做清单与符合性
====================================================================

— 4.1 不做

  ・不做未定义行为：规格里只允许两种情形——「明确报错」或「明确留作实现自由，且可观测」。凡是「怎么都行」，一律等于「谁都不知道」，不许进规格。
  ・不做隐式类型转换（数值字面量的常量折叠除外）。
  ・不做任意宏：只做卫生宏 + 编译期常量求值，够用即止。
  ・不做运算符重载的任意定义：只允许在少数标准接口上实现。
  ・不做运行时依赖下载：依赖是显式步骤 + 清单 + 哈希。
  ・不做 GC 与手动内存的无边界混用：同一模块内二选一，跨模块靠所有权标注。

— 4.2 符合性

  ・目录 conformance/：每个语法点 ≥1 正例 + ≥1 反例。
  ・错误编号稳定且可搜索：HMYR-E0001 这类编号一经发布不再复用。错误信息属于规格，不属于实现。
  ・每个用例声明它检验哪一条规格（用条款编号回指）。

— 4.3 稳定性

  ・已发布语义不改；新增走 edition（版本门），旧代码照旧编译。
  ・规格变更留提案与理由，历史可追（与 KID 的「只增不改、可复审」同一口径）。

6.4 模块系统与 import：三步，两成一半

2026-10-27 重写。这一节原来写着「能解析，装没看见」—— 那是几个月前的状态，现在不是。

  ・第一步 加载：[成] import 真的加载本地文件、同一个文件只加载一次、循环引用被拒（E0301）。
    宿主 loader 与自举层各一份实现，判据在 test/subsetload 与自举层那几套。
  ・第二步 可见性：[成] 2026-10-27 收口。四件东西合起来：
    pub 被子集层认出（以前它直接抛「子集不认这个声明」）；装载层用它在跨模块引用时
    报 HMYR-W0303；求值器有归属表（名字来自哪个模块），运行时按它判断 ——
    跨模块调一个没写 pub 的名字是 HMYR-R0250，同模块里调自家的私有函数不算；
    as 别名真能用（别名点成员走按模块分的声明表，私有名字经由别名同样是 R0250）。
    这条规则能立起来，是因为先做了迁移：tools/pub-census.mjs 盘出 14 + 62 个名字，
    19 个多模块入口全仓归零之后，它才从「记一条」升成「拒绝」。判据在
    test/namespace.test.mjs 第六、七节。
    它中途当过一阵 W0304（只记不拒），而那一段也值得留在记忆里：把既有代码全打红
    的规则不是规则，是一次没做的迁移 —— 先标名字，再开拒绝，顺序不能换。
  ・第三步 包与依赖：[成] 2026-10-27 收口。五件东西：
    包名能解析到实际文件（包根 + index.hmoca），版本用 rev 检查；
    包清单（hmyr.hmkit）四项：名字 / 版本 / 许可 / 哈希，装载器验形状（E0304）；
    依赖与依赖哈希：依赖只写最低版本（区间不做，理由见 design/PKGMAN.txt 第三节），
    缺包是 E0305、版本不够是 E0306、写了依赖没记哈希是 W0305；
    哈希链由 tools/hmkit-check.mjs 比 —— 它挡「换了一个包」，挡不住「换的人同时
    改了清单」，后者要签名，写在设计稿第五节的边界里。
    判据在 test/pkg-manifest.test.mjs 第七、八节，以及 test/owned-check.test.mjs 第十三节。

顺序的理由没变：第三步的后半（包管理）必须有模块系统当前提；而第二步要动求值器，
那是这个仓库里最贵的一次改动。
6. 悬而未决（诚实列表）
====================================================================

  ・内存模型（原 [悬] 1，2026-10-27 全部落地）：三区模型（arena / owned / managed）四台一致，
    帧退出释放、装载时的四层静态检查、跨模块与跨包的借用分析都已有判据。
    见 design/MEMORY.txt 第 2 节。
  ・并发模型（原 [悬] 2，2026-10-27 落地）：结构化并发 + 进程式隔离 + 消息传递；
    取消的两种形态按「谁能被语言调度」分界；效果跨任务只落在派生处。
    见 design/CONCURRENCY.txt（含六个反例与验收）。
  ・编译目标（[定] 2026-10）：先解释器，再 WASM，最后原生。理由：语义先钉住，再谈速度；宿主实现已经有了（src/eval.mjs）。
  ・与 KID 的嵌入（[定] 2026-10）：子进程 ＋ JSON-RPC。宿主授予一组效果，脚本的 main 只能声明这一组的子集，超出即拒（HMYR-R0202）；宿主只提供读取的内置函数 read_text（需要 file 效果），没有写入的内置函数——「只读文件」因此是事实，不是承诺。
  ・工具链命名（[定] 2026-10）：编译器 hibana（火花）· 包管理 kagaribi（篝火）· 格式化器 tomoshibi（灯火）· REPL yu（湯）。取意山丹与火，也留一处给温泉。
  ・标准库第一圈（[定] 2026-10）：数值与序列：abs · min · max · len · int · str · fmt_number（按档案格式化数字，而它不是 str，见 2.8）；输出：print；内存：arena 与 owned（三区模型的头两区：竞技场一次释放全部，所有权格子一次装一个值、取出即转移；第三区 managed 由 freeze／adopt 到达，见 design/MEMORY.txt）；FFI：bytes_view／view_len／view_get／view_set（一段窗口，读写都走它，三个问题的答案见 design/FFI.txt）；文件：read_text（需要 file 效果；宿主不提供写入）与 read_bytes（读原始字节，嵌入与打包要它，同样需要 file 效果）与 read_dir（列一个目录，交回排好序的名字元组，含目录名，同样需要 file 效果；排序由世界那一侧做，因为两台机器必须交回同一个顺序）与 is_dir（问一个路径是不是目录，交回 Bool，同样需要 file 效果；问不到就是 false——「问不到」与「不是」在调用者眼里通常是同一件事）与 校验和（CRC32：收字节元组，元素可以是一字节也可以是一块，交回一个 32 位的无符号数；纯算术，所以不需要效果。多吉性与 ZIP 都要它）；输入：read_stdin_line（读标准输入的一行，交回 {行, 结束}，结束是 EOF）与 read_stdin_bytes（读 N 个字节，交回 {字节们, 结束}）与 bytes_to_text（字节元组按 UTF-8 解码成文本）；进程：run_program（需要 process 效果；必须带超时，缺省 10 秒，被停下的程序会报告 timedOut）；时间：now_ms（不需要效果，但破坏可复现性——要可复现的程序不要用它）。；文件与时间：待加。GUI 与 3D 交给绑定。判据：求值器里的每个内置函数都必须在这一行里点名。

7. 与 KID 的关系
====================================================================

HMYR 不是 KID 的一部分，而是它的邻居：

  ・KID 是「认得、索引、验证」的引擎；HMYR 是「写出东西」的语言；
  ・两者共享同一套脾气（可检验、只增不改、依赖可见、运行时不专属）；
  ・第一个交点是 KPB：谱／混／音色用 HMYR 写，KID 负责验证与打包。

8. 开源定位（本语言是开源语言）
====================================================================

HMYR 是开源语言，这句话不是一句口号，它对我们有具体约束：

  ・规格：文本公开、可自由引用与实现：[定]
  ・实现：参考实现公开；任何人可另写实现：[定]
  ・协议：本体、规格、工具链、美术统一采用自拟的 LicenseRef-CZGD-PL-1.1（チーズ牛丼パブリックライセンス / Cheese Gyudon Public Licence）——见仓库根的 LICENSE-CZGD-PL-1.1.txt：[定]
  ・协议的性质：权利不限用途、不限人群、不分商业与否，并额外许可同人、二次创作与修改后不回馈；未走 OSI 认证，这一点如实写明：[定]
  ・协议的名字：这个名字是有意的：把「チー牛」这个词端上桌并吃完它。前言的定位与理由见协议正文，明确不构成条款：[定]
  ・不牵连：协议不引用、不依附、不代表任何其它团体——吹哨人的职责之一是避免把更多人卷进来：[定]
  ・腰杆：第 0.4 条把「不道歉」写成「挺直腰杆」：公开的自由、不得作为条件、不得贬低、可以大方标注同人／音MAD／DTM、授权人自我约束（不以贬低社群换取接纳）：[定]
  ・优先解释：第 0 节构成条款，歧义时依 O.T.A.K.U. 优先解释，仍不确定则取对行使权利者更有利的读法（待复核）：[定]
  ・符合性套件：公开且可自由使用——不许把「正确」藏在私有测试里：[定]
  ・提案与决策：提案公开、理由留档、变更可追；不设暗门：[定]
  ・兼容性政策：公开的稳定性承诺与版本门（edition）规则：[定]
  ・借来清单：第 3 节那张表本身就是开源义务：故意借用，就要公开致谢：[定]

三条反面承诺（同样重要）：

1. 不做「开源皮、私有关键」：凡影响「一份代码在别处如何表现」的部分，一律公开。
2. 不做「规格私有化」：规格不随实现搬家；换了实现，代码照旧能编。
3. 不做「靠不兼容升级收租」：破坏性变更走版本门，且必须给出迁移路径。

[验] 每一条都有可核对的证据：许可文件、公开的提案记录、公开的符合性套件、公开的兼容性政策文档。

治理（[议]）：轻量但留痕——提案公开、决策者署名、理由成文。不追求委员会式一致，
但也不接受「谁声音大谁说了算」；分歧写成提案归档，日后可回看。
