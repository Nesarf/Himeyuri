关键字：源码层的那二十五个词该叫什么
====================================================================

  这一页定一件事：源码里那二十五个保留词的汉字写法，以及改它的顺序。
  它服务的判据是「语法逻辑独立」—— 现在这二十五个词全是英文，
  而内部构成那一层（错误码七层、三十二种节点名、三十四条指令名）已经换过了。
  也就是说：编译器念的是自己的词，而写程序的人还在敲 return。

  为什么先定表而不是先改代码：这批词出现在每一份 .hmoca 里，
  改一次要动全部源码、全部例子、以及文档里的代码块。
  表定下来之后那些替换是机械的；表没定就动手，同一批文件要改两遍。

一、这些名字从哪来
--------------------------------------------------------------------

  三个来源，按优先次序：

    一、已经落地的节点名。三十二种 kind 换名时定过一批汉字
        （字 名 二元 一元 调用 组 记录 索引 字段 类型名 组类型 记录类型
         函数类型 返回 表达式语句 赋值 当 若 定 变 类型别名 声明语句
         顶层变 函数 模块 常量 引入 宏 效果 块 误）。关键字优先沿用它们，
        于是「编译器内部叫什么」与「写程序的人叫什么」是同一套词。
    二、已经落地的指令名。三十四条操作码里有几个与关键字同名
        （布尔 常量 返回 存储 取 组 记录），同样沿用。
    三、既没有节点名也没有指令名的，才新定。这一批只有四个词：
        真 假 空 判（对应 true false nil match）。

三、替换的三步走
--------------------------------------------------------------------

  做法与 design/FILETYPE.txt 第七节那一次改名相同，顺序也不能反：

    一、工具同时认两套。src/lexer.mjs 的 KEYWORDS 表里两套都收，
        src/parser.mjs 的比较处两套都认，vm/hmyr.c 与 self/lex.hmoca
        的保留字判断同样两边都收。这一步做完，仓库里两种写法都能跑。
    二、批量换成汉字。源码、例子、文档里的代码块、测试里的源码字符串，
        一次换完，旧名一个不留。
    三、删掉旧的那一套判断，跑受影响的套件。

  反过来做（先换源码后改工具）会留下半个仓库两种写法，而那种状态最难查：
  工具认一半，剩下那一半安静地不被认出。

  那一次改扩展名时踩过的五个坑这一条同样适用，尤其这两条：

    一、判断不只在 JS 与 C 里。self/lex.hmoca、self/parse.hmoca、
       src/subset-lex.mjs 各自有一份保留字判断 —— 只改宿主那一份，
       症状是自举层「少认几个关键字」，而退出码仍是零。
    二、文档里的代码块也要换。design/ 那四十四份里有大量 .hmoca 片段，
       它们不参与跑程序，却是下一个人照抄的东西。

四、这一页怎么验收
--------------------------------------------------------------------

  改完之后，源码里不该再有英文关键字。可核的两条：

    一、src/lexer.mjs 的 KEYWORDS 集合里，汉字之外一个不留（旧名可以在
        ALIASES 那一层留一段时间，作为输入别名）。
    二、全仓搜那二十五个旧名，命中的只有设计文档里的「历史名」与
        调试输出标签，源码与测试里的字符串一个都没有。

五、仍然不确定的三处
--------------------------------------------------------------------

  一、true 与 false 是否该做成内置而不是关键字。现在它们在关键字表里，
     而自举层的切词器把关键字一律当标识符（self/lex.hmoca 开头那段写着），
     于是「关键字」在两条路上的行为本来就不完全一样。
  二、nil 与空元组的关系。语言里没有 null，空元组就是它；而 nil 是关键字。
     换成「空」之后，它读起来更像「空元组」，可能与那条设计相冲。
  三、运算符与标点的规范形式。ALIASES 现在让中文标点能进来，而出的一侧
     仍是 ASCII。关键字换完之后，这一条要不要跟着换成中文，是下一步的事。
