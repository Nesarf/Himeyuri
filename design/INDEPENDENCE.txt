独立：六条能验的性质
====================================================================

2026-11-04 起草。这一份替换一句话：「近读法齐了，差 0 格」。

那句话的问题是格子是自己画的 —— 「宿主有几个内置、其中几个在别处也有」
这两个数都由我们定，于是「差 0 格」能成立而独立性未必成立。数字对齐是必要的，
但它不构成定义。

下面六条才是定义，而每一条都指着一个已经存在的判据。一条说不清该看哪个判据的性质，
就不是性质，是愿望。

一、运行时闭包不碰工具
--------------------------------------------------------------------

  从三个入口（src/eval.mjs、src/minimal-eval.mjs、src/vm.mjs）出发，
  顺着 import 走到底，闭包里不能出现 tools/ 下的模块。

  为什么这一条是定义的一部分：工具是我们自己的脚本，不是运行一个程序所需要的
  东西。它们出现在闭包里，说明「跑一个程序」正在借用「我们开发时用的东西」。

  怎么验：tools/runtime-path.mjs 算出三个闭包并报越界数；
  test/crosscheck.test.mjs 第三节把「越界 0 处」与 independence 的「零工具」钉在一起。

二、种子自足
--------------------------------------------------------------------

  一个已经嵌了种子的二进制，在没有 node、没有 bootstrap/pack.hmtn 放在旁边、
  也没有手工编译这一步的情况下，能跑一份 .hmyr 源码。

  为什么：这是「第一次编译之后不需要宿主」的可执行形式。

  怎么验：test/self-contained.test.mjs。

三、种子与编译器互为逆
--------------------------------------------------------------------

  HMYR 写的打包器跑在字节码机上，重新编出来的字节与 bootstrap/pack.hmtn
  逐字节相同。

  为什么：这一条把「种子」从「一份来路不明的产物」变成「这台机器自己也能造出来的
  东西」。两边的字节相同，说明编译器与种子的关系是闭环，不是单向依赖。

  怎么验：tools/self-vm-compile.mjs 第四节（十四项里的最后一项）。

四、世界面：宿主有的，另外两处也有
--------------------------------------------------------------------

  宿主内置表里的每一个名字，C 那台与自举求值器都认得；而自举编译器认得的
  那些名字，也要覆盖宿主那一份。

  为什么：程序在四台机器上跑，而内置是它们共同的底。缺一个名字，就是某一台上
  跑不动某一段源码。

  怎么验：tools/builtin-gap.mjs 的两条「差 0」；test/crosscheck.test.mjs 第二节钉住
  它，并额外要求「自编」那一列不为空（那一列空过一次，报了七十八个假欠账）。

五、三台同答案
--------------------------------------------------------------------

  同一份源码，在最小求值器、JS 字节码机、HMYR 写的 VM 上给出同一个答案 ——
  包括两条失败边界上的退出码与输出。

  为什么：独立性不是「能跑」，是「跑出同一个结果」。三台有一台偏了，
  那门语言就没有一个确定的意思。

  怎么验：test/bytecode.test.mjs 第二节（六条真实路径）。

六、编译期不借宿主
--------------------------------------------------------------------

  自举层解析十进制字面量这件事，由 self/compile.hmoca 自己的 数字值 做，
  而不是转手给宿主那份实现。

  为什么：这一条是「编译期的主权」。字面量的值决定程序的意思，而如果那个值
  要问宿主，那么同一个程序在两边的意思可能不同（这次就是：宿主对了，自举层读成零）。

  怎么验：test/dec-lit.test.mjs 十五项，其中反向那一节把慢路换回旧写法，
  必须看到 1e-320 变成 0 —— 那证明判据抓的是自举层，不是 JS 那一侧。

今天的状态
--------------------------------------------------------------------

  六条都有判据，而且都绿。这不是「齐了」的意思，是「这六条今天成立」的意思 ——
  而「齐」这个字之所以不能当结论，是因为它没有指向任何一条可以被推翻的性质。

  一条要记住的：格子数对齐（差 0 格）是必要条件，不是定义。定义要能说出
  「如果这一条不成立，哪一个判据会红」。

七、剩下这几千行：四段路线第四段的拆法
====================================================================

  四段路线写在 design/FULLSELF.txt 第 50 行起。第四段那一句是：收尾：src/ 与
  vm/ 只剩宿主口；那时比例才是接近百分之百，而剩下的几千行要写清「为什么它们
  必须留在宿主上」。

  这一节把那一句拆开，因为「只剩宿主口」今天量不出一个数来：src/ 与 vm/ 一共
  四十九份、三万一千四百九十八行，而这些行没有分类，于是「只剩」这个词没有对象。

一、先把行分完：五类，覆盖 src/ 与 vm/ 全部
--------------------------------------------------------------------

  2026-11-08 实测。量法是按文件数换行、一份一份加：

    生成的数据   5 份  13882 行  vm 的 pack_seed.h 与四个 ucd- 开头的头文件
    C 机器代码   3 份   6955 行  vm/hmyr.c 与它的两个头
    Stage 0      5 份   2097 行  引导的底
    对照实现     3 份   2471 行  src 的 lexer、parser、eval
    其余 src    33 份   6093 行  工具路线与其余宿主侧

  五类之和三万一千四百九十八行，等于 src 的一万零六百六十一加 vm 的两万零八百
  三十七。一份不多，一份不少。

二、每一类一句「它为什么在那儿」，与「它什么时候不在了」
--------------------------------------------------------------------

  生成的数据。它们不是程序，是表：种子字节与 Unicode 属性。而它们可以被重新造
  出来 —— seed 那一套验「gcc 加种子重建种子」，ucdnfchmyr 与 ucdcasehmyr 验
  「HMYR 写的生成器产出逐字节相同的表」。所以这一类的终点不是搬走，是不必提交：
  既然能逐字节重造，它就不必躺在仓库里。

  C 机器代码。它是第四台机器，跑同一份字节码，不经过 JavaScript。它属于独立性
  的实现，不是宿主依赖 —— 这门语言要在一个没有 JavaScript 的地方跑，那台机器
  就必须由某种系统语言实现，今天那个语言是 C。它的终点写在 PLATFORM.txt 第 19
  到 23 行：等 Yunooka 有自己的字节码机。

  Stage 0。引导的底，不能为零（BOOTSTRAP.txt 第 10 到 12 行）。这一类的终点是
  「不存在」，所以能做的只有缩小与说清。今天 2097 行，是从 1108 长上来的 ——
  补的是它认得下的东西。

  对照实现。宿主的求值器、词法、语法。它们在那儿是因为「每一个论断都可被检验」：
  四台机器同答案这件事需要一台独立实现的对照，删掉它，那些同答案的判据就没有
  对照物。它的终点是：HMYR 自己写的那台 VM 成为完整的对照。

  其余 src。工具路线：格式化器、语言服务器、反射、静态检查、loader 变体。
  这一类的账 toolingledger 已经记着：十九项里搬了十八项，剩下那一项有写下的理由。

三、于是第四段能拆成五步，每步都有验收
--------------------------------------------------------------------

  第一步 把上面那张表变成判据：五类之和等于实测，每类的行数与文档写的一致。
         不做这一步，第四段的进度就只能人工数。它要的是关系式而不是常数式，
         口径见 design/CHECKING.txt 开头那节。

  第二步 给每一类写「终点条件」，而不仅写「为什么它在」。上面第二节是初稿。

  第三步 生成的那一类：把「能逐字节重造」变成「不必提交」。这是全表最大的一块，
         一万三千八百八十二行，而它已经是可重造的。

  第四步 Stage 0 与其余 src：一处一处缩，每缩一次在 OPEN.txt 记一行。这两类
         拿得动，规模都在几千行以内。

  第五步 C 机器与对照实现：各自等一个更大的东西 —— Yunooka 的字节码机，
         与 HMYR 写的 VM 成为完整对照。在那之前它们不算欠账。

四、这一段的终点该怎么说
--------------------------------------------------------------------

  「只剩宿主口」不是一个百分比，是一张每类都有终点条件的表。百分比会让人追着
  一个数跑，而表会让人问「这一类的那一条到了吗」。

  一句话：第四段结束时，这四十九份里没有一份说不出自己为什么还在。至于那些
  说得出理由的，它们等的是别的东西，不是等一支更长的工时。
