字节码指令名：换成自己的说法
====================================================================

  这一页与 design/KINDS-MAP.txt 是同一件事的另一半：那一页换的是树上的 kind，
  这一页换的是字节码里的指令名。两页都在回答「这台机器用自己的话说自己的事」。

为什么这一页比 kind 那一页难一点
--------------------------------------------------------------------

  src/code-file.mjs 的操作码表有 34 条，而操作码就是那条指令在表里的下标。
  所以表一改，号就可能全变。

  但这一条要分清两种情况：

    改名字而不改位置    操作码不变，已有的 .hmoks 仍然读得进来 —— 不用重编产物
    改名字又改位置      操作码变了，所有 .hmoks 都要重编

  所以这一页的做法是第一种：只换名字，位置一个都不动。表里那 34 个位置从此不再是
  「按字母排的」而是「按历史定下来的」，这也与那句注释一致 —— 加指令追加在末尾，
  旧号不动。

  换句话说：这一页要做的是一次纯改名，代价只有「六处引用要一起改」。

34 条与它们的新名字
--------------------------------------------------------------------

  算术与比较

    ADD    加        SUB    减        MUL    乘        DIV    除
    MOD    余        NEG    负        EQ     等        NE     不等
    LT     小        LE     小等      GT     大        GE     大等

  存取与赋值

    CONST   常量      LOAD     取        STORE    存        ASSIGN   赋值
    GLOBAL  全域取    SETGLOBAL 全域存

  跳转

    JMP        跳         JMPT     真跳       JMPF     假跳
    JMPT_KEEP  真跳留     JMPF_KEEP 假跳留

  调用与返回

    CALLF  调函数      CALLB  调内置      CALLM  调方法      RET  返回

  数据

    BOOL    布尔       TUPLE  组          RECORD 记录
    FIELD   字段       INDEX  索引        POP    弃

  34 条正好数完：算术与比较 12、存取 6、跳转 5、调用 4、数据 6、再加 POP 一条。

要一起改的六处
--------------------------------------------------------------------

  一个指令名出现在这六份里，改一处漏一处就会出现「编出来的字节码读不懂」：

    src/code-file.mjs     操作码表本身（名字 → 号的映射在这里）
    src/bytecode.mjs      编译时产指令
    self/compile.hmoca    自举侧的编译
    self/pack.hmoca       自举侧的打包
    src/vm.mjs            JS 虚拟机执行
    vm/hmyr.c             C 机器执行

  而判据是现成的：改完之后 runtime/run.hmoks 要能被两台机器跑出同样的结果
  （c-vm 那套与 vm 那套就是干这个的），再加上 cembed 与 ffi 那两套。

做的顺序
--------------------------------------------------------------------

  与 kind 那一段一样：一次一种，失败的 range 就只有一种。而这一页的作用是让那 34 次
  不必每次重新想名字 —— 名字已经在上面了，剩下的是机械活。

  一个提醒：改文件用 read + edit，不用 PowerShell 的 -replace 做结构化编辑。
  那一段里这根钉子踩过三次（反引号 n 变成字面量、吃掉逗号、U+741B 那种假象）。
