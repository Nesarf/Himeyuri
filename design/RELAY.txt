从 oak-barrels 学来的四条
====================================================================

  E:\oak-barrels 是一个中立中继站：宿主与音频引擎之间的独立桥，Dart 写宿主侧、
  C++ 写站内，MIT，协议文档在 docs/RELAY_PROTOCOL.md。它和 Himeyuri 不是一回事，
  而它的设计里有四条是通用的，值得学过来。

第一条：兼容性是类，不是版本
--------------------------------------------------------------------

  它的协议第 4.3 节说：中继站描述后端时用「兼容类」，而不是版本号。
  engine.action.named 的意思是「有一种按名字触发事情的办法」，而不是「某个构建」。
  理由是版本是短暂的，类才是稳定的。

  落在 src/capabilities.mjs 的 报告()。一份能力用类名回答「我会什么」，
  报告里没有一个字符串来自运行时 —— 全是写死的类名，于是它不会顺手把机器的
  布局或版本说出去。验收在 test/capabilities-layer.test.mjs 的「二·五」：
  本机十八类、空能力零类、报告里没有路径也没有版本样式的串。

第二条：拒绝优于过宣称
--------------------------------------------------------------------

  它的第 10 节与第 6 节都指向同一件事：说不确定的能力，等于说没有。
  一条报错只带原因码与一句不泄露细节的话。

  落在 报告() 的第二半：类由能力对象自己声明（声明 那张单子），
  报告 再对照成员检查一遍。声明了却缺成员的那部分报成「缺」，而不是当成会。
  空能力的单子是空的 —— 它一类都不报，这正是它该有的样子。
  第一版我按「有没有那个函数」去推断，于是空能力（成员全是一调就拒的函数）
  被报成什么都会；那一版已经删掉了。

第三条：借来的东西要能说清--------------------------------------------------------------------

  它的 A2 说：构建期不知道任何东西，版本常量是 bug；A4 说：发现的事实留在内存里。

  Himeyuri 这边对应的做法是能力内核：世界只在 src/capabilities.mjs 里借一次，
  别的层只拿一个对象。这一条早就做了，而 Unicode 那一组是最后补上的。

  没做到的那一半：Himeyuri 的错误消息里带着路径与名字（那是诊断要的），
  而中继站默认不给。这一条记在下面「还没做」。

第四条：出口可替换，名字由调用方给
--------------------------------------------------------------------

  它的第 2 节：三种传输（unix socket / 命名管道 / 标准流），默认不开 TCP，
  名字由宿主选，一个实例只服务一个连接，多来的直接拒绝而不是排队。

  Himeyuri 对应的东西是 write 出口：print 写到一个可替换的出口，套件里换成缓冲，
  示例里换成 stdout。同一条规矩：出口由调用方给，语言侧不发明名字。

  写那一轮时没做的：socket 与命名管道那两种传输，那时语言只有一个标准流出口。
  后来都补上了：命名管道在第十八轮，socket 在第二十轮，见下面「还没做」与「第四个出口」。

不学的部分
--------------------------------------------------------------------

  帧格式（长度前缀、类型字节）、协商报文、音频通道、运行期符号绑定 ——
  前三件是中继站自己的协议，第四件是它的核心技艺（不链接、运行期解析符号）。
  而 Himeyuri 不做中继、不做音频，硬搬只会搬来一层没人用的结构。

还没做
--------------------------------------------------------------------

  一、诊断脱敏。做完了（2026-10-26）：src/redact.mjs 一个开关，启动器认 --redact
      与环境变量 HMYR_REDACT。打开时引号里带分隔符的那一截换成 <path>，编号一个都不动。
      两条路都用它：内置自己拼的消息走 藏路径（我们确知那是路径），
      启动器出门前走 脱线（自举层自己拼的消息不知道开关）。
      验收在 test/redact.test.mjs，十五项。

  二、传输。做了一半（2026-10-26）：启动器认 --out <文件>，print 写到那里，
      而诊断仍走 stderr。这是「出口可替换」那条规矩的第二个用法 ——
      第一个是标准流，第三个会是命名管道或 socket，而它们都不必让语言侧改一行：
      print 只认那个出口对象，出口由调用方给。

      命名管道那一条也做完了（第十八轮）：启动器认 --pipe <名字>，名字按调用方给的用
      （Windows 是 \\.\pipe\xxx，别的机器上是一个 FIFO 的路径）。
      语言侧一行都没改 —— 这正好验证了那条规矩。

      做的时候撞到的两件事，都记在这里：
        一、管道是异步的。end() 之后还有一段在飞，而 process.exit 不会替我们等；
           不等的样子是「输出少了一截，而且只在快的时候少」。所以退出前等 finish 或 close，
           再兜一个两秒的定时器。
        二、连不上要出声。静静地把 print 丢掉，比报错更难查 —— 现在报 HMYR-E0002。

      test/pipe.test.mjs 六项：两行按顺序收到、末尾那一行没丢、程序返回值也走同一个出口、
      连不上时退出码不是 0 且 stderr 里有那个编号、以及标准流那条路没被弄坏。

      socket 也做完了（第二十轮）：启动器认 --socket，形状写在值里，
      见下面「第四个出口」那一节。做它的时候守住了「默认不开网络」这一条 ——
      不带 --socket 时，一条连接都不会被建立。

  三、模块的版本协商。Himeyuri 的 import 没有 revision 概念，
      将来若要给接口加版本，照中继站那条「取双方都支持的最高版本，没有交集就拒绝」。

      做完了（第十九轮）。语法是三处小加法，而它没有变成一件大事：
        模块顶上写   rev N     这个模块提供到第 N 版接口
        import 后面写 import "./x.hmoca" rev M
      协商就是一句：M <= N 就成，否则拒绝，报 E0303，消息里说清两边各是哪一版。
      不写 rev 的那一边不提要求 —— 老代码一行都不用改，这一点是故意的。

      为什么「交集」退化成一个比较：这门语言没有范围语法。模块说「提供到第 N 版」，
      而向下兼容是这个说法的含义 —— 于是「双方都支持的最高版本」就是 min(M, N)，
      而它存在当且仅当 M <= N。等哪天有了范围语法，这一段要跟着改。
      test/module-rev.test.mjs 九项：三种该通过的（相等、要得更低、不提要求），
      四种该拒绝或该说清楚的，以及 rev 后面写不出数字时报错。

第四个出口：socket（第二十轮）
====================================================================

  第四条规矩说「出口可替换，名字由调用方给」。到第十九轮为止，这个名字有三种取法：
  标准流（默认）、--out 一个文件、--pipe 一条命名管道。第二十轮加上第四种：--socket。

  做它的理由很实际：前三种都出不了这台机器。一个把结果交给旁边一个进程的程序，
  与一个要把结果送到另一台机器上的程序，用的是同一行 print，差别只在调用方给的出口。
  既然前三种都做到了「语言侧一行不改」，第四种也该是。

取值形状
--------------------------------------------------------------------

  一条选项，一个值，形状写在值里，前缀说明走哪条路：

    --socket tcp:host:port       TCP。要本机就明写 127.0.0.1 或 localhost。
    --socket pipe:<名字>         Windows 命名管道，名字照写 \\.\pipe\xxx。
    --socket unix:<路径>         Unix 域套接字，只在 POSIX 上有意义。

  为什么是一条选项三种形状，而不是三条选项：argv 里要剔掉的东西少一处，
  而写法本身就说明了走哪条路 —— 日志里出现 --socket tcp:127.0.0.1:7 时，
  读的人不必回头查文档也知道那是一条 TCP 连接。

  切法只切第一个冒号，因为路径里本来就可以有冒号（\\.\pipe\ 里就有两个）；
  tcp: 那一种再从最后一个冒号切一次，于是 host 可以是域名，端口永远是最后那一截。
  IPv6 字面量暂不支持：它自带的冒号与这个切法打架，要支持得先约好方括号写法，
  那是一件值得单独想清楚的事，不该顺手塞进这一轮。

  pipe: 与 unix: 在实现上落到同一个调用（net.connect 收一个名字），分开写只是为了让
  命令行说出意图。Windows 上写 unix: 会失败，POSIX 上写 pipe: 会当成普通路径，
  两种错都会当场出声，而不是安静地连到别的地方去。

默认不开
--------------------------------------------------------------------

  不带 --socket 时，出口仍是标准流，一行都不变。

  为什么网络要显式才开，而不是「反正不联网的程序用不到」：

    一、出口决定的是「输出去了哪里」，而这件事只有调用方知道。默认值取标准流，
        因为它是唯一一个不需要任何人先做决定的去处。一条连接要先有对面的地址、
        端口、以及「此刻有人在听」，缺一件就是失败，而失败是无声的。

    二、网络把失败的可能从本机挪到别处。文件和管道坏了，报错就在眼前；
        TCP 那头有没有人在听，本机看不出来 —— 于是「能不能出得去」不再由
        这台机器保证，而由命令行上那一个字符串决定。这样的东西不适合当默认值。

    三、中继站的第 2 节也是这么定的：三种传输里默认不开 TCP。它的理由是
        「一个实例只服务一个连接，多来的直接拒绝而不是排队」，同一件事的另一面：
        对面不可控，所以门要上锁，不能虚掩着。

    四、默认开只对「几乎总是要、且几乎总是不出错」的东西成立。网络出口这两条
        都占不上，于是它只能被显式要。

  一句可核的话：不带任何出口选项时，启动器里一条连接都不会被建立。
  这一条由 test/socket.test.mjs 的第四组与 test/pipe.test.mjs 的第三组各验一次。

连不上怎么办
--------------------------------------------------------------------

  报 HMYR-E0002，以 2 退出，stderr 里带着能分辨的原因：

    连不上  the socket cannot be opened: connect ECONNREFUSED 127.0.0.1:1
    形状错  the socket cannot be opened: expected tcp:host:port, pipe:<name> or unix:<path>
    没给值  the socket cannot be opened: --socket needs a value, <shape> follows it in the next argument

  三种共用一个编号，因为结果一样：输出没有去处。写开关却不给值这一种最容易被
  当成「没给选项」，于是静默退回标准流 —— 那正是这条规矩要堵的缝。
  退回标准流在哪种情况里都是更坏的选择：静默丢输出，而「只在我这儿少了几行」
  是这份代码里最难查的一种症状。

  这里有一处借来的编号要说清：HMYR-E0002 在语言诊断里已经属于「块注释没有闭合」。
  出口这一处是借用，--pipe 在第十八轮就这么用了。借的理由是编号要能被 grep 到，
  而这一层的失败本来就发生在语言外面。将来若给启动器单独一套编号，这两处要一起搬；
  现在没搬，是因为那会让 --pipe 的既有行为变一次。

  原因照实说。开了脱敏（--redact）而形状里带的是路径时，那一截换成 <path>。
  TCP 的 host 与 port 不换：它们不是路径，删掉反而让人不知道自己在连什么。

程序返回值也走同一个出口
--------------------------------------------------------------------

  与 --pipe 相同：自举层把目标程序 main 的返回值 print 出去之后才返回，
  于是它与那两行走的是同一个出口对象。test/socket.test.mjs 用 return 7 验这一条 ——
  用 0 会与「退出码是 0」读起来混在一起，那是两件事。

收尾要等
--------------------------------------------------------------------

  与管道相同：end() 之后还有一段在飞，process.exit 不会替我们等。
  不等的样子是「输出少了一截，而且只在快的时候少」。所以收尾等 finish 或 close，
  再兜一个两秒的定时器。管道与 socket 共用这一段收尾 —— 它们都是异步的，
  而语言侧仍然一个字都不用改，这正好是第四条规矩想要的形状。

验收
--------------------------------------------------------------------

  test/socket.test.mjs 十三项：两行按顺序到达、末尾那一行没丢、程序返回值也到、
  退出码是 0、连不上时退出码不是 0 且 stderr 里有编号与原因、形状写错时也出声、
  只写开关不给值时也出声、不给 --socket 时标准流那条路没被弄坏（两项）、
  pipe: 前缀连得上命名管道。

  unix: 那一支没有在测试里验：这台机器是 Windows，Node 在 Windows 上没有 Unix
  域套接字；它在 POSIX 上与 pipe: 走到同一行代码，所以不重复验。
  这一句写在这里，是为了让「十三项全过」这句话的边界清楚。
