字节码：执行模型从「走一棵树」换成「跑一串指令」
====================================================================

这一格是什么，不是什么
--------------------------------------------------------------------

  它是 SELFRUN 第三层的第一格。第三层要回答「谁来跑求值器」，而这一格只回答了
  其中更小的一件事：执行模型能不能换成扁平的那种。

    · 它证明的：AST 能编译成指令，一个循环能跑完它们，六条真实路径给出的答案与
      最小的那个求值器一样。
    · 它做到的第二件：元组与记录不再借用 JS 的数组与对象，而是两个带标签的值
      （src/vm-values.mjs）。于是执行器判断值是什么，问它自己的标签。
    · 它没有做到的：执行器仍然在 JS 里跑，数字与字符串仍是宿主的标量，
      而错误仍然靠 JS 的 throw 传播。所以「不依赖高级宿主」这句话现在还不成立。

  说清这一点是因为「换成字节码」听起来很像那件事，而它不是。真正的第三层要把
  错误与标量也拿走，那才是自己的机器层。

  而这一格仍然是必要的前置：一个循环能交给一台机器，一棵树不能。

认的范围
--------------------------------------------------------------------

  与 design/BOOTSTRAP.txt 第九节那张表一致：十一种表达式、五种语句、十六个内置。
  表外的东西在编译时报错，而不是猜。

槽分配（这一层最要紧的设计）
--------------------------------------------------------------------

  HMYR 的作用域是块加函数。而 self/ 那六份里所有函数都是顶层声明，没有嵌套函数——
  于是没有闭包，作用域只可能是函数帧上的槽。分配规则因此很直接：

    参数占 0 到 n-1；每个 let/var 在它所在的块里拿一个新槽；块结束后那些槽不再被引用，
    但也不回收——一个函数帧的槽数取同时活跃的最大值。遮蔽不特殊处理：内层同名声明
    拿一个新槽，查找先看内层。

  实测下来单帧最大槽数是 11，所以这个「不回收」的代价小到不必优化。

  一件不许省的事是可写性：let 的槽不可写、var 与参数可写。宿主那边这件事由作用域链
  在运行时判（R0150），这里同样在运行时判——编译期判会改变行为，因为「改一个不可写的
  名字」是一条要报出来的错，而不是编译错误。

指令集
--------------------------------------------------------------------

    CONST v            压一个常量
    LOAD s             压槽 s 的值
    STORE s, 可写      弹一个值进槽 s
    ASSIGN s           弹一个值写进槽 s（不可写就报 R0150）
    POP                弹掉
    GLOBAL 名          压全局常量（为将来的 const 留位；六份里没有）
    BOOL               把栈顶转成布尔

    NEG NOT ADD SUB MUL DIV MOD EQ NE LT LE GT GE

    JMP n              绝对下标跳转
    JMPF n / JMPT n    弹一个值，按真假跳
    JMPF_KEEP n        不弹就跳（短路用：跳走时栈上留着的就是整个表达式的值）
    JMPT_KEEP n

    TUPLE n            弹 n 个造元组
    RECORD 名们        弹同样多个值造记录
    FIELD 名 / INDEX   取字段 / 取下标

    CALLB 名, 实参数   调内置（效果在调用点检查）
    CALLF 名, 实参数   调函数（效果：被调者的声明不能比调用者的多）
    RET                交回栈顶

  短路那两个指令（JMPF_KEEP / JMPT_KEEP）存在的理由：与 + || 的右边不该被求值，
  而「左边为假就跳」还必须把左边那个值留下当结果。一个会弹栈的跳转做不到这件事。

一处真差别，写在这里免得被当成 bug
--------------------------------------------------------------------

  整段程序那种入口（自举那边的 跑程序带函数）收的是适配层造出来的语句表与函数表，
  不是源码。这一格不去碰那套装置：它跑的是「模块里的函数」，与 runUnit 同一层。

验收
--------------------------------------------------------------------

  test/bytecode.test.mjs 钉三件事：

    一、六份 self/ 全部编译通过：123 个函数、5875 条指令、单帧最大槽 11。
    二、六条真实路径（hello · while 与赋值 · 记录 · import 一件库 · 目标不存在 ·
        语法坏的目标）在字节码虚拟机与最小求值器上给同一个退出码与同一段输出。
    三、执行器与内置表都不再用 Array.isArray 或 typeof 判对象：值自己带标签了。

  第二条是这一格的全部意义所在：两条执行路径给出同一个答案，才叫「换掉了模型」。

还没做的
--------------------------------------------------------------------

  标量仍是宿主的（数字、字符串、布尔、null——它们就是那些东西，换掉没有意义）；
  错误仍靠 JS 的 throw 传播；步数与深度闸照抄那边的数字。
  这几样是第三层剩下的部分，而它们与这一格的性质不同：这一格改的是「怎么跑」与
  「值是什么」，它们要改的是「跑在什么上面」。
