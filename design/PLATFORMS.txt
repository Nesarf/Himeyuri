平台记录：这一门语言在哪些机器上跑过，以及各自的差异

2026-11-05：在 Windows 原生跑过一次全量
--------------------------------------------------------------------

从 pwsh 那一面（不是 WSL）跑 node tools/check-all.mjs，输出重定向到日志：

  WSL（bash）      231 套全过，330 秒
  Windows（pwsh）  231 套全过，383 秒

没有一套因为路径分隔符、盘符或行尾而失败。两处差异，都不是缺陷：

  一、重定向的编码。日志里读到 閫氳繃 而程序打的是 通过。程序发的是 UTF-8，
      而 PowerShell 的 *> 重定向按控制台编码写 —— 于是文件是 GBK，而读它的人按 UTF-8 看。
      问题在重定向那一层，不在程序：同一个日志用 GBK 读回来就是对的。
      跨两条路比较日志的人要知道这件事，否则 diff 看起来像损坏。

  二、速度与慢榜。383 秒对 330 秒，而慢的五套也不同：Windows 上是 inflate 154、
      vmboot 134、sign 109、selfvmcompile 96、curve 94；WSL 上最慢的 curve 约 83。
      那是进程启动的成本 —— 这一份清单要起几百个 node 进程 —— 是平台的形状，不是测试的。

一条这一轮没有确立的事：C 那台机器没有在 Windows 上原生编过再跑。vm/hmyr.c 那条路
在普通全量里走的是 WSL 的工具链，所以上面那 231 套只在那一层的意义上覆盖它。
