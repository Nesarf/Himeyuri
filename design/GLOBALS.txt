模块级可变声明（顶层 var）

  对应 MEMORY.txt 的 §4.2 那一条「能存东西的地方」。那里最后留下的话是：
  「容器要活得比函数久」这个需求已经由 const 持有索引满足了，而真正的
  模块级可变声明是另一种语义。这一页把那另一种语义定下来。

====================================================================
1. 它是什么
====================================================================

  顶层 var 名 = 初值  —— 一个模块级、可写的名字。

  它与 const 的差别只有一条：const 的名字不能重新绑定，var 的可以。
  两者都是模块级的，两者的初值都在程序开始之前算好。

  写法示例：

      var 计数 = 0
      const 上限 = 10

      fn 加一() -> Int {
        计数 = 计数 + 1
        return 计数
      }

  函数里读一个不在槽里的名字，编成 GLOBAL；写一个不在槽里的名字，
  编成 SETGLOBAL。这两条以前就有（读）或这一轮才有（写）。

====================================================================
2. 初始化顺序（第一条要定的规矩）
====================================================================

  [定] 按源码顺序，依赖在前。

  一个模块里，顶层声明按出现的顺序逐条求值；初值表达式只看得见在它
  之前求值完的名字。跨模块时，顺序是 import 的顺序 —— 被依赖的模块
  先求值完，再轮到依赖它的那一份。

  为什么这么定：这是唯一不用再发明一套机制的答案。它也是「读一份文件
  从上往下」这件直觉的直接翻译，而别的选择（收集起来再按依赖排序）
  需要先有一张依赖图，而那件事模块系统今天没有。

  代价写在这里：一个模块里的 var 不能引用同一模块里写在它后面的 var。
  那样的程序会在装载时报「没有这个名字」，而不是等到运行期。

====================================================================
3. 跨模块可见性（第二条要定的规矩）
====================================================================

  [定] 平铺，一律可见，重名先到者赢。

  模块级的名字住在一条平铺的表里，与函数表同一条规矩（见 design/RELAY.txt
  关于「平铺的表让后一个胜出」的那一段记录；那里对函数是先到者赢的补丁）。
  import 的顺序决定谁先到。

  为什么不自作聪明加可见性：

    ・语言里现在没有模块前缀（写不出 模块.名字），也没有 private；
      「可见性」今天只能靠「不在同一个文件里就看不见」，而这一条与
      「跨模块可见」正好相反。
    ・加载器已经会为「两个模块声明同一个名字」报一条警告（W0302）。
      那是一条该被听见的话，而不是一条静默覆盖。可见性这一维等
      命名空间落地时再谈。

  代价写在这里：一次 import 就把对方的 var 拉进同一个命名空间。
  两个模块各有一个「计数」时，后到的那一个被前一个盖住，而唯一的
  提示是装载时那条警告。

====================================================================
4. 与内存模型的关系
====================================================================

  var 存的值仍然住在它的区里：写一个值进 var 不会让它换区，也不会
  延长它的寿命。所以「把一个 arena 块存进模块级 var」仍然要被
  静态检查拦下 —— 那是 design/MEMORY.txt §4.2 的 R0304，而它与
  「块被存进记录」「块被存进索引」是同一件事的两个近形相加。

  换句话说：var 给的是「名字可以重绑」，不是「值可以逃出它的区」。
  这两条正交，而后者由检查器管，不由语法管。

====================================================================
5. 不做的东西
====================================================================

  ・不加锁，也不加原子操作。跨线程共享一个 var 是数据竞争，而这一页
    不假装解决它。设计稿的态度是：线程那边要共享，就该走消息（见
    design/THREADS.txt 的邮箱那一节），而 var 是单线程的便利。
  ・不做「惰性初始化」。初值在装载时算，一次，顺序如第二条。
  ・不做「只读导出」（export let）。可见性那一维等命名空间。
