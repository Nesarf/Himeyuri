引导：Stage 0 的账
====================================================================

  这一份说的是「完全自举」这四个字在实践上能做到哪儿。
  它不给愿望，给数字与路线。

一、为什么 Stage 0 不能为零
--------------------------------------------------------------------

  要跑 Himeyuri 写的程序，总得有一个能跑 Himeyuri 的东西。
  那个东西若是 Himeyuri 自己，它就得先被跑起来——于是要有一个更早的能跑它的。
  这就是引导（bootstrap），而它是递归的底，不是懒。

  编译器界的说法是 Stage 0 编译 Stage 1：Stage 0 是宿主写的那个，
  Stage 1 是产物，而两者在语言设计一致时应当产出同样的结果。
  这一份里的 Stage 0 就是宿主的三个文件。

二、Stage 0 现在有多大
--------------------------------------------------------------------

  实测（2026-10-20）：

    src/loader.mjs     88 行    读文件、跟 import、去环
    src/lexer.mjs     269 行    切词
    src/parser.mjs    445 行    搭树
    ------
    合计              885 行（其中非空行 801）

  两个数都写，因为它们量的是不同的东西：885 是总行数，801 是非空行。
  一份只写一个数的说明，会让读的人以为自己量错了。

  它读 self/run.hmyr 时会带进六份、一百二十三条声明，花三十四毫秒。
  而 bin/hmyr.mjs 三十二行，只做三件事：把那一层读进来、递 argv、按退出码退出。

  要说清的是：求值不在 Stage 0 里。求值由 self/eval.hmyr 做，
  而 Stage 0 只负责「把那六份变成一棵树」。于是这一门语言「怎么算」的答案，
  已经全在 self/ 里；Stage 0 只回答「怎么读」。

三、已经成立的那一半
--------------------------------------------------------------------

  六份全对（见 design/SELFCOMPILE.txt）：把 self/ 里每一份交给自举的函数名们，
  它算出来的函数名与宿主算出来的完全一致，默认栈，三到五秒一份。

  于是「它能读自己」这一句是真的。而「它读自己」用的还是 Stage 0 的词法与语法——
  那两件事正是还没交出去的部分。

四、再缩的办法：子集到底要什么
--------------------------------------------------------------------

  目标是让 Stage 0 只支持「跑 self/ 里那六份所需」的子集。

  为了知道子集里必须有什么，把六份源码扫了一遍。结果（2026-10-20）：

    语句      六种：Block · Return · ExprStmt · Let · Assign · Var
    表达式    十一种：Ident · Literal · Binary · Call · Field · If ·
                     Record · Index · Tuple · Unary · While
    运算符    十四种：! != % && * + - / < <= == > >= ||
    字面量    三种：bool · int · string

  而 If 与 While 在这一门语言里也是表达式（if 有值），于是它们既算语句也算表达式。
  这一点值得单独说，因为第一次扫漏了它——那时数出来的运算符只有五种，
  而「只有五种」那个结果看起来很干净，差点被当成真的。

  有了这份清单，一个手写引导器的规模能估出来：单是这些构造的切词与求值，
  三四十行是不够的，三五百行更接近实际。那份文档原来写「三四十行」，
  在这里改正——一个偏小的估计比一个偏大的估计更容易骗人。

  而缩到零不在路线里。任何声称「零引导」的说法，底下都藏着一个没被说出来的 Stage 0。

五、这一份数字会变
--------------------------------------------------------------------

  test/bootstrap.test.mjs 钉着第二节与第三节的数字：
  Stage 0 的行数、六份文件数、声明数、以及六份全对这件事。
  数字变了它会红，红的时候先读这里。

六、第一步已经落了一格：切词层对得上了
--------------------------------------------------------------------

  src/subset-lex.mjs 是一个一百来行的子集切词器。它现在：

    六份一致   lex 1988 · chain 2137 · stmt 1252 · body 1285 · eval 2687 · run 2246
               token 的种类、值与顺序，与 src/lexer.mjs 逐个相同

  那处分歧（换行折叠的位置）查清了，而且它只有一个成因：ident 与 keyword 那一支
  用 出.push 而不是 记()，于是「这一行最后一个 token」停在更早的运算符上，
  续行() 把真实的行尾误判成续行，把那一个 newline 吞掉。

  一个笔误，六份里的四份各差几个 token，而症状看起来像「换行规则理解错了」。
  前一版这份文档写着「追踪过两次没查清」；查清它的办法不是再读一遍那段规则，
  而是把两个切词器并排喂同一份源码、逐 token 报出第一个分岔与它的行列。

  位置也跟着来了：行从 1、列从 1，每推进一个字符若不是换行就加一列，token 记的是
  它第一个字符的位置。那套算法是照 src/lexer.mjs 抄的，而 CRLF 里那个 \r 也占一列——
  照抄这一条是有代价的：不照抄，同一份用 CRLF 的源码在两边会差出一列。

  于是「六份一致」现在含位置，报错也带得上行号与列号了。

  还差的是范围而不是规则：转义表只认 \n \t \r \\ \"，以及它不认全角标点的别名
  （宿主有一张 ALIASES 表，而 self/ 那六份里没有用到全角标点）。

  它仍然不接线到任何地方。理由变了一点：以前是「半成品不该被套件钉住」，
  现在是「它还没有自己的立场」——它目前只证明能对齐，而 Stage 0 要的是能替代。
  test/subset-lex.test.mjs 钉着这件对齐的事（含位置），也钉着那个笔误的具体形状
  （行尾是一个 ident、而它前面是运算符时，那一个换行必须出得来）。

  这一步量到的东西也有用：把 Stage 0 的切词那一层（269 行）压到一百行出头，
  而压下去的办法是「只认用得到的东西，遇上不认的就报错而不是猜」。
  那与这份文档第二节那个八百行是同一件事的两端。

  离「能用」还差：转义表补全，以及全角标点别名。

七、第二层：搭树，六份的树已经一样了
--------------------------------------------------------------------

  src/subset-parse.mjs 是子集 parser 的第一格。它认的构造是先数出来的，不是照语法书抄的：

    声明   只有 fn，123 个；没有 type / const / effect / pub，没有类型参数，没有 requires/ensures
    参数   258 个，全部带类型，没有默认值，没有 own/borrow
    类型   只有三种：Int 189、String 65、Bool 4，全是单名
    语句   六种：let / var / assign / return / ExprStmt / Block
    表达式 十一种：Literal · Ident · Binary · Unary · Call · Index · Field · Tuple · Record · If · While
    运算符 十四种，五档优先级（与 src/parser.mjs 的 PRECEDENCE 同一张表）

  那份普查连带钉住了一件事：六个文件里一个 import 之外的顶层构造都没有，
  于是子集 parser 的规模不是「语法有多大」，而是「这六份用了多少」。
  而它照样会碰到别的写法，所以每一条不认的构造都各自报错，并说清是哪一行哪一列。

  验收是两棵树整棵深比较，连字段名与每个节点的行号列号一起比：六份全部相同，
  25 · 20 · 10 · 14 · 26 · 28 个函数，合计 123；节点合计 6285，位置逐个相同。

  位置起初是分开做的（先形状、后位置），理由是两者混在一起查，红了说不清是哪一边的事。
  而位置那一格只查出一种取法要照抄：Field 记的是「字段名之后那个 token」的位子。
  宿主如此，这里照办——照抄的理由是「两棵树一样」这句话要经得起逐节点核，
  而单方面改对一处，就等于把两棵树拆开。Block 只带行不带列，也照抄：
  缺一个字段与有一个错的字段不是一回事。
