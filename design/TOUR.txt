看一眼 Himeyuri：给第一次来的人

它长这样
--------------------------------------------------------------------

    fn main() -> Int {
      var i = 0
      while i < 3 {
        print("第 " + str(i) + " 次\n")
        i = i + 1
      }
      return 0
    }

  跑它：node bin/hmyr.mjs 你的文件.hmoca

  就这些。没有 package.json，没有 tsconfig，没有 bundler，没有 node_modules。
  整个仓库是一堆源码，而它跑起来只需要 Node。

它主张什么
--------------------------------------------------------------------

  一、说了、做了、跑得到，是三件事。
     所以每一处能力都有三条线钉着：代码里有、契约里写着、套件里验过。
     tools/check-builtins.mjs 就是为此存在的——它对着三面看，缺一面就报。
     而全部七十个错误编号，每一个都有一句中文人话（conformance/plain.mjs）
     与至少一条能触发它的用例。

  二、边界写在明处。
     做不到的说做不到，不装作支持。数一数这个仓库里写着「未做」「缺」「还没」的
     地方就知道——那些不是不好意思提的事，而是这个项目的一部分。

  三、语言达不到就先动语言。
     与其在调用处绕一个弯，不如把语言补上。slice、ord、chr、to_int 都是这么来的；
     while 是这么来的；reader macro 也是这么来的。

  四、谁动世界谁声明。
     读文件、起进程、开线程都要在函数签名后面写 effects(...)。
     一个只声明了 file 的程序调 chdir 会被拒绝——那条规矩是真的在跑，不是装饰。

  五、零构建。
     源码就是运行的东西。那意味着改一行就生效，也意味着没有「构建产物」这回事。
     发布是另一件事：self/release.hmoca 一条命令出清单、归档、说明书三样，
     而 tools/release-loop.mjs 把发出去的东西拿回来、用 HMYR 自己的 verifier 验一遍。

它和别的不一样在哪
--------------------------------------------------------------------

  ・它是自举的：self/ 里那一套用自己的语言写了词法、语法、语句与求值，
    而启动器把目标程序交给那一层，不是交给宿主。
  ・它有终端：画布、场景栈、帧循环、节拍、字形，全在 term.hmoca 里，
    而每一帧都能被套件断言（输出可注入）。
  ・它能算颜色：sRGB 到 CMYK 的可测量转换，两套具名策略，
    而报告的那几项判定是在语言里做的，不是在宿主里。
  ・它读模块音乐：pattern 美化与 MOD 头部，学自 openmpt 的做法。

它现在还不能做什么
--------------------------------------------------------------------

  ・还不能完全独立：执行器仍跑在 Node 上。最终目标是「完全独立的计算机语言」，
    而那要一个最小的机器层（见 design/SELFRUN.txt 里的三层）。
  ・板子上还没有：桌面那第二台机器验过了，vm/hmyr.c 与 Node 那台逐字对拍八十项，
    而它在一颗真芯片上跑过这件事还欠着。这一条等硬件，不是等代码。

  语言服务器那一条已经不在这份名单里了：initialize、documentSymbol、definition、
  hover、completion 都通，definition 还能跨 import 跳到别的文件（self/lsp.hmoca，
  验收是 lsp、lspsymbol、lspcompletion 与 lspmodule 四套）。

想深入的时候
--------------------------------------------------------------------

  design/TOOLING.txt     这份代码从哪儿学的、改了什么
  design/CAPABILITIES.txt 九组能力与它们的效果
  design/AUDIT.txt       一次通查与逐条对照的记录
  design/DISTRO.txt      一个发行版该有什么，以及这里到哪儿了
  design/SELFRUN.txt     最终目标与三步路线
  design/PKGMAN.txt      一个包怎么说明自己：清单、版本、依赖、哈希链、签名
  design/HMGET.txt       一个包怎么进来、又怎么拿掉：来源、校验、卸载的三条规矩
  design/BOARD.txt       跑在一块 Cortex-M4 板子上：四层证据与它装得下多少
  conformance/plain.mjs  七十句中文，一句一个编号

  而想先看形状而不是文字的时候：

    node tools/impact.mjs --map                整张工程地图：谁 import 谁、每个套件加载了什么
    node tools/impact.mjs self/body.hmoca       给一个文件，答「改动会碰到哪些套件」而不必试跑
    node tools/hmget.mjs --from <来源> --into <包根> <包名>   取一个包（只从文件，不联网）
    node tools/hmget.mjs --remove --into <包根> --dry-run <包名>  说清会删什么而不动手
