宿主能力契约（自举第一步）

为什么要有这一份
--------------------------------------------------------------------

  现在宿主提供了四十一个内置，它们散落在求值器里，只有源码知道各自做了什么。
  而「用 HMYR 启动」这件事的前提是：「宿主是什么」得先变成一份可替换的清单。
  所以下面按能力分组，每组写清四件事：成员、语义、要不要效果、拒绝时给哪个编号。

  换宿主时对着这一份逐组实现，同一份 .hmyr 的行为就该一致；
  不一致就是契约没写清，先补契约，不先改宿主。

分组
--------------------------------------------------------------------

  一、文本（纯函数，无副作用，不需要效果）
      slice ord chr to_upper to_lower to_int
      len str int abs min max
      nfc is_letter is_mark split
      语义：只从输入算出输出，不读也不写任何外部状态。
      拒绝：ord 空串给 R0206；chr 越界给 R0207；to_int 非整数写法给 R0208。

  二、输出
      print
      语义：写一行到一个可替换的出口（套件里换成缓冲，示例里换成 stdout）。
      拒绝：无。它不失败，只会写不出去——而写不出去是宿主的事。
      效果：print 不需要效果。它写到一个可替换的出口（套件里换成缓冲），不算动世界。
            这条是设计决定，不是遗漏：谁要真的写文件或起进程，才需要 file 与 process。

  三、文件（需要 file 效果）
      read_text write_text
      语义：读时编码要么显式写明，要么按 BOM 判——BOM 是事实，代码页是猜测，所以只认前者。
            写时只编得出 utf8、latin1、utf16le 与有表的那几个；写不出就拒绝。
      拒绝：编码不认识给 E0008；表缺失给 R0203；字符编不了给 R0204。
      返回：写入的字符数（不是字节数）。
      编码名有别名：utf-8 与 utf8 同义，utf-16le 与 utf16le 同义；大小写不论。
      走表的那条路：逐字符查表，缺的字一次全报（前八个 + 还有多少个）；先查齐，再写，不写半个文件。

  四、进程（需要 process 效果）
      run_program chdir
      语义：跑一个程序（必须带超时，缺省十秒）或改变进程的工作目录。
      返回形状：run_program 交回一个记录，字段是 code（没有退出码时为 -1）、stdout、stderr、
                timedOut 与 error（跑不起来时带宿主的错误码，例如 ENOENT）。
                记录是对外的事实，不是异常：跑不起来也照实报告，不抛。
      两个细节：stdout 与 stderr 的尾部空白被去掉；而一次最多收 8 MB，超出时 spawnSync 报 ENOBUFS，
      那个码出现在 error 字段里，而不是另设编号。
      第四个参数是输出的编码：中文 Windows 的控制台多半是 GBK，写死 UTF-8 会让每个汉字变成替换字符。
      拒绝：进不去的目录给 R0209；程序名为空给 R0213。

  五、环境（只读，不需要效果）
      cwd home_dir locale_env locale_current locale_set console_codepage
      repo_path python_path temp_path
      （仓库根、解释器位置与临时目录：语言文件里不写死绝对路径，换机器也不用改）
      语义：读宿主的位置与语言环境；locale_set 只改「当前选的是哪一套」，不改任何文件。
      拒绝：没有那套语言档案给 R0205。

  六、时间（不需要效果，但破坏可复现性）
      now_ms sleep_ms floor
      语义：读时间、等一会儿、向下取整。
      注意：要可复现的程序不该用 now_ms。这一条写在第一圈里，不是事后提醒。

  七、终端（只返回字符串，一个字都不写出去）
      term_size term_clear term_escape term_color term_hide term_show
      语义：把终端控制序列当作值交回，由调用者决定写给谁。副作用留给 print。
      拒绝：无。它们不失败，只会给出一串没有用处的序列。

  八、输入（队列加真终端的同步读，不需要效果）
      key_push key_available key_read key_start
      语义：真实终端与套件走同一个队列。而 key_read 有三种情形，三种都要说清：
            一、队列里有东西：立即交回一个键。
            二、队列空而 stdin 是终端：同步读一次 stdin，阻塞到有键为止，一次最多读 64 字节，
                读完把多出来的推进队列（于是 key_available 才有意义）。
            三、队列空而 stdin 不是终端：立即交回空串——不阻塞，也没有键。
      为什么用同步读而不是 data 事件：求值器是同步的，而 sleep_ms 是忙等，
      事件循环在那一刻堵着，事件永远送不进来。同步读绕开了这件事。
      拒绝：无。没有键就是空串；而 key_start 在非 TTY 下如实返回假，不装。

  九、记录（按名字造、按名字取）
      record_new field_get field_has
      语义：记录不是哈希表——record_new 只收「标识符能写的名字」，否则拒绝（R0214）。
            field_get 取不到会拒绝（R0216），而 field_has 只回答有没有（纯函数，不需要编号）。
      为什么它们在这一组：自举的求值器要按节点上的名字现场造记录，那时候
            名字是个变量，写成 .名字 写不出来。而 x[名字] 也不行——下标只收数字。

  十、线程（需要 thread 效果）
      thr_spawn thr_join thr_cancel thr_count
      语义：worker 在另一个核上跑，结果经文件送达，共享内存只发「写完了」这一个信号。
            为什么不用 postMessage：那个回调也在主线程的事件循环里，而主线程正堵在
            Atomics.wait 上。隔离是硬的——worker 有自己的求值器实例。
      拒绝：句柄不存在给 R0221；等超时给 R0222。起不来就交回 -1（无效句柄），不另设编号。

  十一、内存（三区模型未实现前的宿主桩）
      arena
      实现现状：只有 alloc(n)、close()、held() 三个。design/MEMORY.txt 里写的 freeze 与 adopt 还没实现——
      那是设计超前于实现，写在这里免得有人以为能喊 freeze。这一组的契约以 MEMORY.txt 为准，
      而以「实现现状」这一行说清此刻到哪儿。

这一份与第一步的关系
--------------------------------------------------------------------

  写完这一份之后，「能力收敛」还差两件：
    一、把散在这个文件之外的行为差别消掉（例如文件读不到时现在只抛宿主的原始异常，
        没有稳定的编号——那就该补一个编号，因为「拒绝时给哪个编号」是契约的一部分）
    二、让求值器里的内置实现逐组与这一份对齐，组与组之间不再有交叉引用。

  这两件做完，第二步才有意义：换宿主时对着这一份逐组实现，而不是读求值器的源码。
