契约：requires 与 ensures 的运行期那一档
====================================================================

SPEC §2.4 的第三只旋钮写着两句话：不写就不查；写了但证不出来，就运行期查。
第一条今天已经成立（写了也等于没写）。这一页立的是第二条。

一、它在什么时候跑
--------------------------------------------------------------------

requires   函数入口。参数已经绑进作用域，体还没开始。
ensures    函数出口。两条路都算：正常走完，以及中途 返回。

多个 requires 或 ensures 按书写的顺序逐个求值，每一个都要成立。
第一个不成立的立刻停 —— 后面的不再求值，因为契约的意思是「全部成立」，
而一条已经破了，再多说几句也没有用。

二、条件里能看见什么
--------------------------------------------------------------------

requires 的作用域就是参数：参数名直接可用。

ensures 的作用域多一个名字：返回值。
它不在关键字表里，是一个普通标识符，所以不会与参数名撞车。
（真有一天有人把参数叫 返回值，这个设计要重看 —— 写在明处比留着好。）

边界也写在明处：条件表达式今天不受纯度限制。写进契约的表达式如果调了一个会写
文件的内置，它就会写。这不是承诺，而是「纯度检查还没做」这个事实；
将来要加强是在这一层加，不是在使用者那边加。

三、失败报什么
--------------------------------------------------------------------

    HMYR-契-001   requires 不成立
    HMYR-契-002   ensures 不成立

「契」是新的码族，与 詞（词法）、形（语法）、行（运行）、載（装载）、內（宿主）并列。
两个码都登记在 conformance/codes.mjs，都由 test/contracts.test.mjs 指着。

消息里带函数名与条件的序号，因为一个函数可以有好几条 requires：

    HMYR-契-001  函数 取(f, n) 的第 2 条 requires 不成立

四、开关：为什么放在环境里
--------------------------------------------------------------------

    HMYR_CONTRACTS=1   这一跑打开契约检查
    不设，或设成别的   关（弱档，也就是今天的行为）

与 HMYR_GC、HMYR_ZONES 同一条先例：这一跑我要改，写在环境里，不写进源码，
也不改语言的语义。

为什么不写成语法开关：硬条款一要求「关掉检查的程序与打开检查的程序行为一致」。
两个字节流要跑出同一个答案，语法层就不能在这里分叉。

五、那条硬条款怎么验
--------------------------------------------------------------------

一条契约都成立的程序：开关两边跑，输出逐字相同。
一条契约不成立的程序：关档时跑得过去（那是今天的样子），开档时在第一个不成立的
那一条上停住，码与函数名都说得出。

两条一起才说明「只改检查强度」是真的 —— 只有前一条，说明检查没生效；
只有后一条，说明检查会改变正常程序的行为。

六、今天做到哪一步（诚实的界线）
--------------------------------------------------------------------

五台都做了，而它们的开关位置不同，这一点值得写清：

    src/eval.mjs          运行时开关。options.contracts 为真，就在调用那一层查。
    src/vm.mjs            编译期开关。要查就把契约编进函数入口，不查就不编。
    src/minimal-eval.mjs  运行时开关，与 eval 同形。
    vm/hmyr.c             不需要自己的实现。它执行的是已经编好的字节码，而检查是
                          编译器编进去的，所以它只要认「契约失败」这个名字就够了。
    self/eval.hmoca       运行时开关，走命令行（--contracts）。这一台是「解释」那一条路，
                          也是 bin/hmyr.mjs 不给 --compile 时用户真正走到的那一条。

C 那台是这一件里最省的一步，而它省得有道理：契约检查住在编译器，不在机器。
两台机器执行同一份字节，就该给出同一个答案 —— 判据因此不是「它自己也查一遍」，
而是「同一份字节在它那里停在同一个码、同一句话上」。

两台求值器的分工要认得：bin/hmyr.mjs 的默认路用 最小运行 跑的是自举解释器，所以
minimal-eval 查的是「解释器自己有没有契约」；而用户程序里写的契约，由自举解释器里的
求值器（self/eval.hmoca）在它执行那段源码时查。

第二台为什么放在编译期：字节码里没有「跳过一段检查」的指令，要在运行期决定
就得加一条新操作码，而那要四台一起认。编译期决定便宜得多，代价是两个档是两个
字节流 —— 而硬条款一要的是「程序的行为一致」，不是「字节流一样」，两台的用例都验了。

那条口子已经收掉了，而且是按「让子集解析器认契约」这一条路收的：src/subset-parse.mjs
现在认它们（同一位置、同一形状、按出现的顺序收进 requires 与 ensures）。于是
--compile 那个入口点得到了，实测三件事：关档跑过去、开档且契约成立照常跑、
开档且契约不成立停在 HMYR-契-001 上并以 1 退出。

为什么不走另一条（让 --compile 换用宿主 reader）：启动器顶部那段注释说得清楚，
它用子集那两层是有意的 —— Stage 0 里不再有 src/lexer.mjs 与 src/parser.mjs 被调到。
换 reader 会把那条性质撤掉，而认契约只是让子集那两层多认一种写法。

自举编译器那一处也补上了。self/compile.hmoca 原来只读声明的头四件（名、参数名册、
语句批、效果名册），第九格的契约从不打开 —— 于是拿它编一份带契约的源码，那些条件会
静默消失：没有错，没有警告，只是不再查。今天它读第九格，并把两端编成字节：
入口是 requires 再 invariant，出口是「返回值落槽、查 ensures、查 invariant、取回返回值」。
那个形状与 src/bytecode.mjs 那一份逐条相同，连失败那句话也逐字相同。

这一位原来没有档 —— 编源码 不带选项，编出来的一律是强档流。当时的理由是：
自举链要证明的是「HMYR 能编出与 JS 那份同样的字节」，两个档是两个字节流，
比哪一份都得先对齐档，于是让 JS 那一份跟着开强档就够了。

2026-11-02 它有了档：编源码 的第二个参数是 1 强档、0 弱档。落地很省 ——
进 编函数 时把契约盒换成空契，入场与出场两段自然空掉、返回值 那个槽也不占；
循环不变式不在盒里（它挂在 当 那一行上），所以在 编循环不变 那里单独看一次档。
状态记录因此从五件变六件。

判据现在有三层。一、tools/self-vm-compile.mjs 逐字节比两台编译器（强档对强档）。
二、同一套的「二半」：带契约的两份样本，弱档对 JS 的 contracts:false 逐字节相同，
且弱档与强档字节不同 —— 后一条盯的是「档是不是摆设」，只比同一档的话，一个被
忽略的参数也能全绿。三、test/contracts.test.mjs 第十三节让子集编出的字节跑在 vm 上，
坏契约要停在 HMYR-契-001，而那句话与另外五台逐字相同。

只有第一层，说明两边错得一样；只有第二层，说明不了子集交的就是同一份字节；
只有前两层，说明不了「编出来的东西真的会查」。

自举那一台最费事，而难处不在求值：自举层的声明元组原来是八件
（名、参名册、语句批、效册、行、列、返型、是公开），里面没有契约的位置。
加进去之后函数是九件（第九件是契约），宏是十件（第九件是 "macro" 那个标记，
所以契约只能排到第十件）—— 长度不同是有意的，读契约的地方因此要知道自己读的是哪一种。

它的开关也与另外四台不同，理由写在代码里：这一层读不到环境变量（locale_env 交回的是
语言环境猜测，不是环境），而 argv 本来就是它的。所以 --contracts 出现在目标程序的
参数里就打开检查 —— 与 HMYR_GC 那几条同一条分工：这一跑我要改，写在启动那一行。

还有一处形状要认得：自举这一条路的失败与另外四台不同。self/run.hmoca 的 跑模块族
把运行期的错包成「错：…」当成正常文字交回去，于是 命令行入口 打印它并以 0 退出。
那不是这次改出来的，是这一层既有的选择；判据因此看输出里有没有那个码与那句话，
不看退出码。若将来那一层改成非零退出，判据要跟着改，而不是两边都放宽。

所以今天的状态是：五台全查，两台编译器都编。SPEC §2.4 的「三只旋钮只改检查强度」在五台上都有判据 ——
同一个开关在每一台上都不改变「契约成立」的程序的行为，而在每一台上都让「契约不成立」
的程序停下，并且给出同一句话。
