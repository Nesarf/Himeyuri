HMYR 的 AST 节点：旧到新（32 种）

这份表是自立那件事的第二份产物。第一份是错误码（design/CODES-MAP.txt）—— 它把
「报错时念什么」换成了自己的说法；这一份换的是「树上的节点叫什么」。

为什么值得换：kind 的取值是树的形状被叫出来的名字，而它现在全是 JS 生态的通行写法
（Binary、Literal、Call、Ident、Block）。借语法可以（入口要便宜），借形状不行
（形状是身份）—— 这句话在错误码上用过一次，在树上同样成立。

改的规矩与错误码那条相同：产生与消费两端一起改，改完跑全量确认行为一条没变。
而这一层比错误码更险，因为 kind 的取值会被索引、比较、以及下游的编译与求值读。

----------  ------------  --------------------------------------------

字          Literal       值本身
名          Ident         一个名字
二元        Binary        两边的运算
一元        Unary         一边的运算
调用        Call          调一个函数
组          Tuple         一组值
记录        Record        一组有名字的值
索引        Index         取第几个
字段        Field         取某个名字
类型名      TypeRef       一个类型引用（Int、String 这类）
组类型      TupleType     元组的类型
记录类型    RecordType    记录的类型
函数类型    FnType        函数的类型
返回        Return        交回一个值
表达式语句  ExprStmt      一条只有表达式的语句
赋值        Assign        改一个已有的名字
当          While         循环
若          If            分支
定          Let           定一个新名字（不可改）
变          Var           定一个新名字（可改）

没进这张表的那九种，因为它们不是 AST 节点：

  int  string  nil  type   这四个是字面量的 type 字段（值本身，不是节点）
  punct  newline          这两个是记号（token）的 kind
  effect  plaintext  view 这三个是别的层的字段

改的时候按文件逐份换，换完跑一次全量确认行为一条没变。

落地情况（2026-11-02）：全部 32 种已经换完。全仓搜旧名只剩 3 处，而它们都是故意保留的：
  test/host-deps.test.mjs  两处，JS 内置清单里的 Error（TypeError 那一类）
  tools/loader-swap.mjs    一处，找报错文本用的 l.includes("Error")

而替换的过程留下了五条方法，记在这里给下一次：
  一、先查「这个词在别处出不出现」—— 独特词可以一次换
  二、查大小写 —— Ident 与 ident 是两个完全不同的东西
  三、一次一种节点 —— 失败的范围就只有一种
  四、查拼接串 —— join 之后的 kind 名与带引号的 kind 名是两种形状
  五、分批：干净的批量做，撞别处的一个一个来，必要时按文件排除
