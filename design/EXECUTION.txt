执行模型：协作式调度之上的真线程

两层，不是一层
--------------------------------------------------------------------

  一、协作式调度（sched.hmoca，已验）：几件事交错推进。它不让计算变快，
      但让「同时在路上的几件事」说得清——取消、完成、失败不连坐都在这一层。
  二、真线程（本文）：几件事真的同时跑在两个核上。单位是「一个任务整个跑完」。

  两层不冲突：调度器决定「轮到谁」，而轮到的那一个可以交给一个线程去跑完。

关键的判断：为什么这次可行
--------------------------------------------------------------------

  子进程那次（parallel.hmoca）走不通同步等待，因为子进程的完成事件要靠主线程的事件循环，
  而同步等待正好把事件循环堵死——两件事互相等，谁也动不了。

  真线程走的是另一条通道：结果不经主线程的事件循环。
  具体是：worker 把结果写成文件，而主线程与 worker 共享一块 SharedArrayBuffer，
  那块内存里只放一个数字——「写完了」。主线程用 Atomics.wait 等这个数字，醒来再去读文件。
  字符串放不进共享内存（它只能放数字），所以结果只能走文件。这一条是实测得来的，不是设计时就想好的。

  也就是说：
    ・子进程：数据回来要经过主线程的事件循环 —— 同步等会死锁。
    ・真线程：信号经共享内存、数据经文件，两者都不经过事件循环 —— 同步等成立。
  这不是偏好，是两条通道的性质不同。

语言侧的形状
--------------------------------------------------------------------

  thr_spawn(源码, 入口函数名)   起一个线程，交回句柄；需要 thread 效果
  thr_join(句柄)                同步等它结束，交回它交回来的那段文字
      等法：缺省超时三十秒，每五十毫秒查一次那个共享信号（Atomics.wait）。
      醒来之后读结果文件，读完删掉它；读不到（文件没了、或 JSON 坏了）就交回空串，不报错——
      那不是「拒绝」，是没有结果可交。而不管成没成，句柄都会从表里删掉：
      一个句柄只能 join 一次，第二次会得到 R0221。
  thr_cancel(句柄)              叫停它；需要 thread 效果
  thr_count()                   现在有几个线程活着（调试与断言用）

  入口与返回值都是字符串。理由与邮箱那条一样：传值是拷一份，不是共享一个引用。

隔离是硬的，不是约定
--------------------------------------------------------------------

  这是这一格最值钱的地方：worker 里跑的是一个独立的求值器实例，
  它有自己的堆、自己的函数表、自己的名字。于是「任务之间不共享可变内存」
  不是靠自觉，而是靠根本没有共享的东西。

  代价也照实写：所以每次跨线程传值都是一次序列化（这里是字符串）。
  想要共享大块数据，得另走「共享类型」那条路，而这一版没有。

效果与编号
--------------------------------------------------------------------

  thr_spawn / thr_cancel 需要 thread 效果（它们会起线程、会叫停线程）。
  thr_join 与 thr_count 不需要——一个是等，一个是读。
  另外 thr_spawn 起完之后会 unref 那个 worker：不让一个还活着的线程拖住整个进程。
  而 worker 自身出错（不是「算错」，是线程漏了）也写同一个信号（值 9），于是 join 不会永远挂着。
  起不来（连 worker 都建不出）则交回 -1，一个无效句柄；join 它得到 R0221——一条路，不是两条。

  R0221  句柄不存在（join 一个已经结束的，或拿错句柄）
  R0222  等超时（线程没在给定时间内结束）

不做什么
--------------------------------------------------------------------

  ・不做抢占：worker 之间没有优先级，也不被调度器切分。
  ・不做共享可变状态：要传值就走字符串，要共享就走将来的共享类型那一层。
  ・不让线程自己再起线程：nesting 留给下一版，先不假装支持。

关于可移植性（补记）
--------------------------------------------------------------------

  这一格的实现依赖 Node 的 worker_threads。它不是三个运行时都有的东西，
  所以在 tools/conformance.mjs 里被登记为「专有模块」，而不是塞进可移植集合里当它存在。

  别的宿主若有等价物（Deno 与 Bun 都有 worker，浏览器有 Web Worker），
  照 capabilities 那份契约实现同一组四个函数即可——而 isolate 的语义要靠那个宿主的线程模型去落实。
  这一点写在这里，是因为「借能力」不等于「假装它到处都有」。
