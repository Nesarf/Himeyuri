一份发行版该有什么：照 Nyarch 数出来的七样

对照是怎么来的
--------------------------------------------------------------------

  本机 WSL 里装着一个 Nyarch（wsl -l -v 里那个默认发行版）。进去数一数：

    pacman -Q  | wc -l     1358 个包
    pacman -Q  | grep nyarch   七个

  也就是说：一个发行版是「99% 借来的 + 1% 自己的」，而那一成里最先的两样
  是仓库（密钥环与镜像列表）——不是内核，也不是桌面。

七样，以及这里对应到哪儿
--------------------------------------------------------------------

  nyarch-keyring / nyarch-mirrorlist     它自己的仓库与它的密钥
    对应：半。

      密钥这一半做了（2026-10-19）：用 OnlySign 造了一张自己的证书，
        O=Himeyuri, CN=Himeyuri · thumbprint A92209B0…C6C701 · 有效至 2031-10-19
        私钥（.pfx）与它的密码在 E:\DaShaoHuo\keys\himeyuri\ —— 仓库之外，不入 git
        公钥（.cer）在同一处造出来，而它是可以发布的：验证方需要它，而它本身不泄密

      而这一半有一个必须写下来的事故：造证书时密码只显示一次，而它显示在
      一次会话的输出里——于是它进了那次会话的转录。严格说来这一张的密码
      已经不算秘密了。要真正保密，重造一张，而这一次别让它进任何日志。

      签什么这一半仍未定：OnlySign 认的是 PE（可执行产物），而这一版出的是
      zip（tools/package.mjs）。两条路都在：把启动器包成 PE，或者让验签的路认 zip。
      那是一个「谁信什么」的决定，不是顺手能做的。
  nyarchwizard      第一次装的时候的向导
    对应：有（tools/wizard.mjs）。它什么都不装，而每一项检查都说清「要不要紧」——
    「没有 python」与「没有 node」不是一个量级，混在一起说就等于没说。

  nyarchtour        装完之后教人怎么用
    对应：有（design/TOUR.txt）。写给不知道的人，而不是写给做的人——
    它说这门语言主张什么、和别的不一样在哪、以及它现在还不能做什么。

  nyarchcustomize   改外观
    对应：有。reader.hmyr（改语法的读法）与 format.mjs（改排版）——
    都是「让用的人按自己的习惯改」，而不是「让作者改源码」。

  nyarchassistant   出问题时的助手
    对应：做了第一版（tools/helper.mjs）。它建在 conformance/codes.mjs 上，
    而不是另起一套说法——给编号就答「什么意思、谁在验它、该怎么办」，
    给词就在含义里搜，搜不到就把全部编号列出来。
    还欠的一样是数据：五十六个编号缺一句中文人话（含义是英文的），
    而那是这个助手最该有的东西，也是最容易做假的——要一句一句写。

  nyarchupdater     怎么拿到新版
    对应：有（tools/update.mjs）。它能答的是「我是哪一份」与「远端有没有新的」，
    而取不到远端时说「不知道」——不是顺手说「你最新」。那两句话差得很远。

  nyarchscript      一组现成的脚本
    对应：有。tools/ 里那五个（check-all · conformance · check-builtins ·
    check-docs · bench）就是这一样。

已经齐的七样，与它们各自的边界
--------------------------------------------------------------------

  至此 Nyarch 那七样在这个仓库里都有了对应的东西。而每一件都带着自己的边界：

    仓库      内容寻址 + Ed25519 分离签名；只验这一个仓库的清单
    脚本      九件工具，各带套件
    助手      建在编号表上；五十六句中文，一句一个编号
    定制器    reader macro 与格式化器；都是给用的人改习惯的
    向导      不装任何东西；要紧与可选分开说
    导览      写给不知道的人；它链接的每一份文档都验过存在
    更新器    能说「不知道」；而「不知道」不等于「是最新」

  第八样：发布渠道。它定为 GitHub Releases（用户 2026-10-19 的决定），
  而 tools/release.mjs 做的是「准备」那半：打包、写发布说明、列出资产。
  真发要 --upload，而那一步没有被跑过——本机有 gh 2.101.0 且已登录（scopes 含 repo），
  于是它大概是通的，而「大概是」不等于「验过」。这一句留着，等真发过一次再改。

  发布说明写三件事，照 S.M.Y.T. 的规矩：哪些资产带签名、哪些没有与为什么、
  以及怎么在不装本项目任何工具的情况下自己验。第三件最容易漏，而它恰恰是
  收东西的人最先需要的那一句。

  一、仓库与密钥。没有它，「发行版」只是一个文件夹。
  二、向导。没有它，第一次用的人要读源码才知道怎么起。
  三、导览。没有它，用的人不知道这门语言主张什么——而主张正是它存在的理由。
  四、清单。没有它，说不出「这一份装了什么」。

  前一样比其他三样都重：它决定别人能不能信任这一份东西。

已经成立的对照，写在这儿免得从零想
--------------------------------------------------------------------

  内核（十五个内置）        已有，且由第四面守着小库只用它们
  标准库（runtime/）        有了第一件（text.hmyr，用到其中五个）
  工具                      五件，各有套件
  约定                      设计文档 · 套件 · 三面与第四面 · 错误编号表

不做什么
--------------------------------------------------------------------

  ・不为了「像个发行版」就去仿它的外观。Nyarch 的桌面与主题是它的，
    而这里的样子该由这门语言自己的主张决定。
  ・不在仓库那一样上偷懒。那是发行版的第一步，而不是最后一件事的装饰。
