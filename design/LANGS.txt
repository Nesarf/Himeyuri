三台机器与一座城市：语言分层的判据
====================================================================

为什么这一份不是「把 JS 换成 Rust」的计划
--------------------------------------------------------------------

  用户的方向是三层分工：中重量级语言为核心建设参考，轻量级语言辅助优化，
  专门类语言介入针对性开发。方向是对的，而「降低 JavaScript 使用率」这句话
  落到这个仓库上会指向一个错的行动 —— 因为使用率按什么算，决定了该动哪里。

  按文件数算，三百四十二个 .mjs 里二百二十三个在 test/；按行数算，四万四千
  二百一十一行里二万五千三百七十五行在 test/。无论哪个口径，第一大的那块
  都是测试脚手架，而测试脚手架本来就该留在轻量级语言里。

  也就是说：若以使用率本身为目标，最省力的一步是重写测试，而它换不来任何
  架构收益。所以这一份不打算把使用率当目标。它要给的是另一条口径，以及
  这条口径下的具体缺口。

三台机器，而不是一台主机
--------------------------------------------------------------------

  这个仓库里同时有三台能跑 HMYR 的机器，而它们的边界不一样：

    机器一   src/*.mjs        源码 → 词法 → 语法 → 求值／编码。全在 JS。
    机器二   vm/hmyr.c        字节码 → 结果。不经过 JavaScript。
    机器三   self/*.hmoca     HMYR 写自己的词法、语法、求值、编译。跑在
                              self/host.mjs 这一个 JS 宿主上。

  三台不是冗余，是这条工程最值钱的东西：两台机器对同一份输入给同一个答案，
  才使得「规格」与「实现」是两个词。design/INDEPENDENCE.txt 六条性质、以及
  test/crosscheck.test.mjs 与 test/c-vm.test.mjs，量的正是这件事。

三层分工，每层在这个仓库里的落点
--------------------------------------------------------------------

  一、中重量级 —— 核心语义的参考实现

    这一层管「同一份源码，两个独立实现，同一个答案」。语言里属于它的：
    词法、语法、作用域与闭包、字节码编码、求值。判据是交叉验证，不是行数。

    现状：机器二与机器三都在，但它们都从字节码起跑 —— 源码到 AST 这一段
    只有 JS 一份。见下一节。

    选哪个语言属于这一层：Rust、C#、Java、C++ 各有代价，见本文末。

  二、轻量级 —— 脚手架与胶水

    这一层管「让判据跑起来」，不管「答案是什么」。属于它的：test/ 的
    二万五千行、tools/ 里的一次性普查脚本（census、gap、dump 那类）、
    bench/、发行脚本的粘合。

    限制只有一条：核心语义路径上不许出现它。判据不是「JS 有多少行」，
    而是「src/ 里每加一个 .mjs 之前，有没有问过它属于哪一层」。

  三、专门类 —— 链接期与裸机

    这一层管「换一种语言能直接换到别的东西」。属于它的：port/ 的 .ld 链接
    脚本、.sct 分散加载、.s 汇编、deps/ 那 23 个 .icc，以及隔壁 Yunooka 的
    NASM。它们是「这件事只有这种语言做得到」，不是「顺手用这个」。

    HMYR 自己也在这一格里长出来：它是给 KID 那层用的领域语言。

缺口：前端只有一台机器（这一条是这一份的实际内容）
--------------------------------------------------------------------

  design/C-VM.txt 与 design/INDEPENDENCE.txt 都说「跑程序这条路上没有
  JavaScript」。这句话今天对字节码执行成立，对源码到 AST 不成立：

    ・lexer 与 parser 只有 src/ 那份 JS。机器二与机器三都吃字节码。
    ・机器三（self/）写了自己的词法与语法，但它跑在 self/host.mjs 里 ——
      那是一个 JS 宿主。所以它不是「没有 JavaScript 的前端」，它是
      「用 HMYR 写的前端，跑在 JS 上」。

  于是「集百家之长」的这条路只修了一半：执行可以不靠 JS，读源码必须靠 JS。
  这一条不是猜测，它由 test/crosscheck.test.mjs 的覆盖范围直接给出 —— 它
  比的是两台 VM 的字节码结果，没有比过两份 AST。

  补法是把前端也变成两台。而它有一个现成的好处：判据不用新造。同一份源码
  喂给两份前端，比较的不是 AST 的内存形状，而是它编码出来的字节码 —— 那
  已经是 crosscheck 在做的事，只是把入口从字节码上移一层到源码。

顺序：先搬哪一段
--------------------------------------------------------------------

  按被依赖度排，src/ 的前六名是 loader（被 135 个文件依赖）、lexer（71）、
  parser（63）、eval（57）、cc（53）、capabilities（39）。按行数排，前端那
  几份（lexer、parser、subset-lex、subset-parse、diagnostics）合计最重。

  两个口径在这里指同一处，所以第一步是明确的：第二份前端，从词法与语法起，
  不从求值起。理由是求值的语义面最宽（闭包、异常、内存三区），而词法与语法
  的输出是一个可以被字节比较的东西；先做能比的那一段，判据才立得住。

  第二步是 capabilities.mjs：design/HOSTMIN.txt 已经量过它要什么 —— 十个宿主
  全局、八种语言构造、一个同步模型。那份清单就是这一层的验收，不必重写。

门禁
--------------------------------------------------------------------

  一条可检查的规矩，替代一个不可检查的比例：

    ・src/ 下新增的 .mjs 必须有理由，理由里要写它属于哪一层。属于核心语义的
      不得以 .mjs 新建 —— 已有的不强制迁，新开的不许再添。
    ・test/ 与 tools/ 不限语言，但 tools/ 里凡进入发行产物的那几份
      （release、package、verify、manifest 一路）按核心对待。

  这条门禁可以写成一条判据：读 design/LANGS.txt 里那张清单，与 src/ 的实际
  文件对账，多出来的 .mjs 要求它在清单里出现过。这一条尚未实现 —— 本文件
  先立规矩，判据在下一格里补。

四个候选，代价不一样
--------------------------------------------------------------------

  第二份前端用哪种语言，是一个会跟着好几年的选择。四者的差别不在性能：

    ・Rust：与 design/MEMORY.txt 里那条「全所有权，安全最强，但学习曲线把
      下限压死」直接相接 —— 它是这门语言读过并部分采纳的那一套。好处是
      与 C 那份机器二能接（FFI 直通），且没有运行时；代价是开发速度，以及
      这份前端会被写成「安全实现」，与规格里「所有权是可选硬档」不完全一致。
    ・C#：与 SPEC 借来清单里「C# / Java：丰富类型系统、泛型、大标准库、LSP
      与调试器」直接对应。它给的是工程性 —— 调试器、反射、大标准库，正是
      「能用」的门槛。代价是运行时体积，以及它不好直接进裸机那一侧。
    ・Java：与 C# 同一档，差别在这台机器上更小；选它的唯一理由是习惯。
    ・C++：与 vm/hmyr.c 与 port/ 最近，头文件能共用，进裸机的路最短。代价是
      它本身就是 SPEC 里「不做未定义行为」这条要防的东西。

  这四个不是等价的。选哪个取决于下一步要买什么：买「与规格自洽」选 Rust，
  买「工程与调试」选 C#，买「与现有 C 那份最短路径」选 C++。

这一份怎么被检查
--------------------------------------------------------------------

  本文的三条主张各有落点，没有一条是只在文档里出现的借用：

    ・台数的账：tools/ 或 test/ 里的一条普查，数各语言的文件与行数，与本
      文件第二节的表对账。尚未写。
    ・缺口那一条：test/crosscheck.test.mjs 目前只从字节码起跑，把入口上移
      一层即是对它的扩张，不是新判据。
    ・门禁那一条：读本文件第六节的清单，与 src/ 实际文件对账。尚未写。

  两句尚未写，与 INDEPENDENCE 那次同一个理由：先立判断，再立判据，而判据
  落下之前这文件里的数字就是它自己的证据。
