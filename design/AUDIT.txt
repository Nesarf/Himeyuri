内置的逐条对照（这一遍的记录）

为什么留这一份
--------------------------------------------------------------------

  通查做了第二层：把每个内置的契约与实现逐条对一遍。
  而对出来的那几处全是同一类——契约写的是写设计时的以为，实现是实测之后的样子。
  把它们记在这里，是因为「差在哪里」比「改好了」更值得留：
  下一次（或下一个人）就不必再从头惊讶一遍。

对过哪几条，各自差在哪
--------------------------------------------------------------------

  arena
    契约（MEMORY.txt）要求 freeze 与 adopt，实现只有 alloc、close、held。
    那不是错，是设计超前于实现——已在这一组里写明「实现现状」，免得有人以为能喊 freeze。

  write_text
    契约只说了编码与拒绝，而实现一直有三件：返回写入的字符数（不是字节）、
    编码名有别名（utf-8 与 utf8 同义、大小写不论）、走表时先查齐再写
    （缺字一次全报，绝不留下半个文件）。三件都补进了契约。

  thr_spawn
    契约说「结果写在那块共享内存里」，而实测字符串放不进共享内存（它只能放数字），
    所以结果走文件、内存只发一个信号。契约还列着 R0220（已改成交回 -1），
    也没提 unref 与 worker 自身的错误信号。四处都补了。
    期间还发现一处自相矛盾：上面改对了，下面两句仍说「数据回来经过共享内存」。

  key_read
    契约说「只读队列、收不到就是空队列」，而在真终端下它会阻塞到有键为止。
    现在三种情形都写清了（队列有／TTY 空阻塞／非 TTY 空立即），
    连「为什么用同步读而不是 data 事件」也写了。

  run_program
    契约有返回形状，而缺三件细节：stdout 与 stderr 的尾部空白被去掉、
    一次最多收 8 MB（超出时 ENOBUFS 出现在 error 字段里，而不是另设编号）、
    第四个参数是输出的编码。

  thr_join
    契约只说「同步等它结束」，而实现里有：缺省超时三十秒、每五十毫秒查一次信号、
    醒来读文件并删掉它、读不到就交回空串、以及一个句柄只能 join 一次。

没逐条对的部分，以及为什么
--------------------------------------------------------------------

  ・print 的实现只有一行，没什么可对。
  ・term 那六个只返回字符串，而拒绝路径在契约里已经写明「无」。
  ・locale 那三个与 cwd／home_dir／chdir 在改的过程中顺带看过。
  ・求值器内部（evalExpr、execStatement）不是内置，它们由套件负责。

性能测量（2026-10-19，这一台机器，Node v24.20.0）
--------------------------------------------------------------------

  node tools/bench.mjs

    词法 self/eval.hmyr（8 KB）      2.070 ms
    语法（同一份）                   1.981 ms
    一万次 while 循环                2.410 ms
    一百次函数调用                   3.724 ms
    自举的词法，扫一段十六行         93.715 ms
    整屏画一帧                       1.002 ms
    差异：一行变了                   1.011 ms
    差异：什么都没变                 0.865 ms
    字节：整屏 830 · 差异 59（省 93%）

  两件值得记住的：

    一、自举的词法比宿主的慢约四十五倍（93.7 ms 对 2 ms 量级）。
        那是「自己写自己」的代价，而它是可测量的，不是猜的。

    二、差异输出省的是字节（93%），不是时间（1.011 ms 对 1.002 ms）——
        时间花在比较上。所以它换来的是「不闪」与「不淹滚动缓冲」，
        而不是「跑得更快」。这一条写在这里，免得被当成性能优化。

  一处要说明的：「一百次函数调用 3.724 ms」那一段把 parse 与建 Runtime 也算进去了，
  所以它量的是「跑一小段程序的总开销」，不是单次调用的开销。

这一遍没做的事
--------------------------------------------------------------------

  ・没有验证语义本身对不对——那是套件的活，逐条对照只能查「说了没」。
  ・没有在第二台机器上跑过（只有这一台）。
  ・没有做格式化器与语言服务器（那是另一个量级，不属于「对账」这一步）。
